# ng psp store — A3: reading a header off a file, including one no reader will open

*Implementation report, 2026-08-26. Step A3 of
[the psp store plan](../../ng/impl_plan/psp_file_format.md), branch `ng-psp-encoding`. Design
authority: [spec §6.6 and §6.7](../../ng/spec/psp_file_format.md),
[arch §4.2](../../ng/arch/psp_file_format.md).*

---

## 1. What it does

`ng::psp::read_header(path)` returns a file's [`Header`] and touches nothing else — no footer, no
index, no block.

**It exists for the file every other reader refuses.** A run killed part-way leaves a psp with a
header, some blocks and no footer, and `PspReader::open` will reject exactly that (goal 3: a file
that is not complete must not be read short). But such a file still *has* a header, so a tool
reporting what a half-written file was going to be needs this — and so does anything checking that a
cohort's files agree on a reference before a run commits to them, which is spec §6.6's second reason.

**A newer format comes back as `UnsupportedVersion`, not as a parse failure.** That is the step's
own contract in the plan, and it works because A2 reads the version from a bare TOML table before
interpreting the body as this version's shape.

## 2. Assumptions and departures

**None that change the design.** One implementation choice worth stating:

**The declared body length is bounded before a buffer for it exists.** `read_header` reads the fixed
12-byte prefix — magic and length — checks the magic, checks the length against
`MAX_HEADER_BODY_BYTES`, and only then sizes a buffer. The alternative, reading the file and handing
the bytes to `Header::decode`, would let a corrupt file's length field drive the allocation before
anything had believed it. The review of A1+A2 flagged this seam in advance: *the guard needs to move
to the I/O seam or be repeated there*.

## 3. Changes made

[`src/ng/psp/mod.rs`](../../../../src/ng/psp/mod.rs) — `read_header`, and eight tests. No other file
changed; nothing outside `src/ng/psp/` is touched.

## 4. Tests, and the mutations they were checked against

**Eight tests, all on real files on disk** (`tempfile::tempdir`, as the rest of ng's file-touching
tests do):

| test | what it pins |
|---|---|
| a header reads from a file that has no footer | the case the function exists for: a header followed by 8,192 bytes that are not a footer |
| …and from a file that holds nothing else | a writer killed before its first block |
| a newer format says so rather than failing to parse | the step's own contract — `UnsupportedVersion`, on a body carrying a key no 1.0 reader knows |
| a production `.psp` is refused as a foreign file | both formats use the extension; this says which it was handed |
| cut short inside its header, refused at every cut | every truncation from 0 bytes to the whole header, and then that the whole header still reads |
| a declared length outside the reader's bound | 0, the ceiling + 1, and `u64::MAX`, each in a 12-byte file — if the bound were checked after the allocation this test would not return |
| a missing file names itself and the operation | `Io { while_doing: "opening the file" }`, not a bare OS message |
| an empty file is refused for being too short | there are no bytes to say which format it is |

**Four mutations run, three killed on the first pass and the fourth killed after a test was added.**

| mutation | outcome |
|---|---|
| read only the body, not the sentinel | **killed** — 4 tests |
| skip the magic check | **killed** — 1 test |
| accept a zero-length declared body | **survived**, then killed |
| — | |

The survivor is worth recording because it is the shape this project keeps finding. Dropping
`body_bytes == 0` passed all 45 tests: a zero-length body is still caught, but *further in*, where
the file is refused for **ending early** rather than for **the length it declared** — and those are
different things to tell whoever is holding the file. The bound test now covers both ends, and
re-running the mutation against it fails that test.

## 6. Tradeoffs and follow-ups

- **`read_header` reads the whole header into one buffer**, at most a megabyte and once per file.
  The reader Milestone D builds will want the same bytes and should not read them twice; that is
  `PspReader::open`'s to arrange, not this function's.
- **The 1 MiB cap is now reachable from two places** and is the same constant in both. Whether the
  cap itself is right is open — the A1+A2 review measured it as a ceiling at about 11,300 contigs
  with MD5s, which is [deferred to Checkpoint A](../reviews/ng_psp_a1_a2_2026-08-26.md#6-deferred--for-checkpoint-a).
