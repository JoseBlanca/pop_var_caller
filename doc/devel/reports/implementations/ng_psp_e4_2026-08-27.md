# ng psp store — E4: the derived residual, and the check that guards it

*Implementation report, 2026-08-27. Step E4 of
[`../../ng/impl_plan/psp_file_format.md`](../../ng/impl_plan/psp_file_format.md), branch
`ng-psp-encoding`. Design authority:
[`../../ng/spec/psp_chain_id_encoding.md`](../../ng/spec/psp_chain_id_encoding.md) §4 and §5.*

---

## 1. What the step is

**One observation's reads are not stored. They are the live set minus every other observation's.**

The live-set changes in a record's head already carry the union of the reads that record names
(E3). Storing every observation's own list beside them writes that union a second time — so one
list is left out and derived, and the largest one is the one worth leaving out. That is where the
column's saving is (spec §4), and where the whole scheme fails silently:

> *"If the reader derives one id too many, the reference observation gains a read that does not
> exist, and the merge will happily compose an allele for it."*

## 2. Decisions taken here

### 2.1 The residual is named, and named as the largest list

Spec §4: *"The residual observation is named, not inferred … removes any guessing about which 'the
reference one' is when observations split by witness and by read group."* Being named frees the
choice, so it is **the observation with the most reads** — the largest saving. Ties go to the
lowest index, so the choice is a function of the record alone and the file is the same at any
worker count (spec `run_streaming.md` §12.1).

It costs one varint a record, `residual-observation`, whose sentinel for *none of them* is the
observation count itself.

### 2.2 ⚠ A record the derivation cannot reproduce stores every list

**A chain id names a read *pair*.** If both mates cover one record and show different sequences,
the same identifier is in two observations — and the derivation, which is the live set minus the
others, drops it from the residual. Spec §4 assumes that away; **Checkpoint E asks for chain ids
that round-trip *exactly*.**

So the writer derives, compares against the list it was given, and **falls back to storing
everything when the two differ**. The cost is one record's residual list. The alternative is a read
silently missing from the reference allele, which is the failure §5 names.

### 2.3 And the writer never produces a record its own reader would refuse

The reader's guard (§3) is an inequality between a derived list's length and its observation's read
count. **The writer checks the same inequality before it derives**, and stores every list when it
does not hold. Without that, a record whose counts do not describe reads would be written and then
refused by the reader that wrote it.

Real evidence always satisfies the inequality — an identifier names one read or two — so this
fires only on a record whose `num_obs` and `chain_ids` disagree, which is a fixture rather than a
sample.

### 2.4 The lists sit in the skippable body

The changes carry state and ride in the head (E3). **An exception list carries none**, so it stays
in the body, behind the byte count a reader skips with — which is spec §6's split, now built on
both sides. They are the ~3.4 % of ids production stored before the 2026-08-17 ruling.

## 3. The guard

There is no second copy to compare a derived list against, so the check is against a number the
record already carries:

- **at most `num_obs`**, because an identifier names at least one read and the list is
  deduplicated;
- **at least half of it**, because at most two mates share an identifier.

It is the same inequality the walk's own differential against production asserts
(`src/ng/locus_generation/pileup/parity.rs`). It does not catch every wrong answer — nothing cheap
does — but it catches the shapes that matter: a derivation that lost the subtraction, one that
subtracted the wrong set, and a live set carrying reads no observation named.

## 4. What the tests are

Four new in `ng::psp::record`, and the Milestone C1 test that existed to fail on this day.

| test | what it forces |
|---|---|
| `the_largest_list_is_derived_and_the_record_reads_back_exactly` | the choice, and the round trip |
| `a_read_named_by_two_observations_makes_the_writer_store_every_list` | §2.2 — a read whose two mates disagreed here |
| `reads_counted_but_never_named_stay_out_of_the_derived_list` | spec §5's other trap: `reads_without_observation` and `reads_discarded_by_cap` are read counts with no identifiers behind them, and a read the depth cap discarded is in no observation — so if it reached the live set the residual would gain a read nobody folded |
| `a_derived_list_that_cannot_describe_its_reads_is_refused` | the guard, in **both** directions, by damaging one byte of a record the writer did derive |
| `the_chain_ids_round_trip_exactly` | **⚠ was `chain_ids_come_back_empty_and_nothing_else_changes`**, written at C1 with the note *"the day E lands, this test is what fails if the ids are still being dropped"*. This is that day |

## 5. Falsification — eight defects injected

| defect injected | tests failed |
|---|---|
| the residual is not derived — every list is stored | 3 |
| the residual's list is stored as well as derived | 7 |
| the derivation subtracts nothing | 2 |
| the derivation subtracts everything live | 3 |
| **the read-count inequality is dropped** | 1 |
| only the upper half of the inequality is kept | 1 |
| **the writer does not check the derivation is exact** | 1 |
| the residual index is always written as zero | 69 |

Eight for eight.

## 6. ⚠ The format changed, and the golden bytes with it

`the_fixture_encodes_to_these_exact_bytes` carries the one assertion in the module that does not
come from the code it tests, under a rule: *never regenerate it to make a test pass; a change here
is a change to the format.* It changed, deliberately — two body fields arrived and `BODY_FIELDS`
moved with them.

**The version did not rise**, for the reason `RECORD_HEAD_FIELDS` already gives about its own
additions: no psp file exists yet, so there is nothing to be incompatible with. From Milestone F,
which writes files that outlive a build, a change here costs a version.

## 8. What Checkpoint E leaves

- **The chain ids round-trip exactly**, including identifiers that go live twice — which is what
  the checkpoint asks.
- **What is not measured is what it costs.** Spec §7 wants the compressed bytes of the column, the
  reader's peak resident live set, and a full scan against a seek, on both corpora. None of that
  can be taken until Milestone F opens a file; the figures quoted throughout Milestone E are the
  spec's own, from a prototype over alignments, not from this writer.
- **The residual's fallback has no measurement either.** How often a read is named by two
  observations of one record — a pair whose mates disagree where they overlap — is unknown, and it
  is the difference between the saving as designed and the saving as built.
