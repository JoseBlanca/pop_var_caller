# ng psp store — H2: an interrupted write is refused

*Implementation report, 2026-08-28. Step H2 of
[`../../ng/impl_plan/psp_file_format.md`](../../ng/impl_plan/psp_file_format.md), branch
`ng-psp-encoding`. Design authority: [spec §6.3, §6.6](../../ng/spec/psp_file_format.md),
[arch §8](../../ng/arch/psp_file_format.md).*

---

## 1. What the step is

**Kill a writer before `finish`, and require every reader to refuse what it left.** That is goal 3
of the format: a killed pileup must not be readable as a sample that covered less of the genome,
because the two are indistinguishable once the file is read short.

The step also closes a carried-forward item: **`refuse`'s `Io` arm had no test**, and the reason it
had none is the interesting part.

## 2. What was already covered, and what was not

`a_writer_dropped_without_finishing_leaves_a_file_with_no_footer` (F3) drops a `PspWriter`
in-process, and `every_truncation_of_a_finished_psp_is_refused_without_panicking` (F4) cut a
finished file at every sixteenth byte. So the *shape* was covered. Two things were not.

**⚠ Dropping a writer in-process is not a kill.** `BufWriter` implements `Drop` by **flushing**,
so an in-process drop puts on disk everything the writer had *closed a block over*; `SIGKILL` runs
no destructor, so the blocks still in the buffer are lost.

⚠ **The first version of this section claimed much more than that, and the H2 review measured all
of it false.** It said the killed file "can end anywhere at all — part-way through a compressed
block, or part-way through the header", and that the state is "unreachable from inside the
process". Three measurements:

- the killed file ends **on a block boundary**, five runs of five, because each block reaches the
  `BufWriter` in one `write_all` and this fixture's blocks average 57 bytes against an 8 kB buffer;
- a `PspWriter` given 58,251 pushes and then **dropped** leaves a file **byte-identical** to the
  killed one;
- and a drop does not flush "everything the writer had produced" either — the records inside the
  open block are not in the `BufWriter` at all, so **5 of 40 records, 12.5 %, are lost** on F3's
  own fixture, with the cut at a *block* boundary rather than a record one.

**What the kill does prove is the mechanism end to end on a real process**, and — since the fix
below — that the writer was **still writing** when the signal arrived. The mid-block state is real
and is covered by the exhaustive truncation sweep, which manufactures every cut.

**And nothing had ever produced a failing `read(2)`.** The obvious way to break a walk does not
break it in that way: truncating a file under an open reader gives an *end of file*, which the
stream correctly reports as a truncated file — a different class with a different instruction.

## 3. Decisions taken here

### 3.1 The killed writer is a real process, got by re-executing the test binary

The only program in the tree that writes a psp is this test suite, so the child is this binary run
again with an environment variable that makes the test take a writer branch instead. The parent
waits until blocks have reached disk, sends `SIGKILL`, and reaps it.

⚠ **The child pushes until it is killed, and that is a correction.** It first pushed a fixed 80,000
records and then slept — and the review measured that the whole workload takes about **5 ms** while
the parent kills at about **12 ms**, so in **25 runs out of 25** the child had finished and was
asleep when the signal arrived. A writer that has stopped writing is not what this test is about.
It now pushes until a deadline, bounded by the contigs' own lengths, and **touches a marker file
only if it stops of its own accord** — which the parent requires to be absent. Forty million
pushes is about 2.5 s of work against a kill at 12 ms, where the version it replaces lost the
race.

**The child's death by signal 9 is asserted, not assumed.** Without it the test could be passing on
an ordinary exit — which would run every destructor, including the flush the test exists to
prevent. The wait is bounded, so a child that never writes fails the test rather than hanging it,
and the child parks after a fixed number of records rather than looping, so a parent that dies
leaves no process filling the disk.

### 3.2 The failing read is a write-only descriptor, not a closed one

**A genuine `read(2)` failure without `unsafe` and without a platform trick.** The walk is handed a
descriptor opened **write-only on a real psp** — the bytes on disk stay a valid file, so the only
thing wrong is that this descriptor cannot be read from. Seeking succeeds; every read fails with
`EBADF`, errno 9, on Linux and macOS alike.

The alternative considered and rejected was closing the descriptor out from under an open `File`
with `libc::close`. That produces the same errno and is a flaky-test generator: the test harness
runs tests on parallel threads, so another thread opening a file can be handed the freed number,
after which the read succeeds against the wrong file.

**The class has to survive the trip**, and that is what the test holds: a read failure must arrive
as `Io` and not as `CorruptBlock`. *Rebuild the file* is the wrong instruction for a disk that went
away, and the file may be perfectly sound — in this test it demonstrably is, because the same
bytes are read successfully through a second descriptor first.

### 3.3 A contrast test, because one of the two classes alone proves nothing

`a_file_that_ends_inside_a_block_is_damage_and_not_an_io_error` walks a file cut one byte short of
its last block and requires `CorruptBlock`. Without the pair, `Io` and `CorruptBlock` could be
swapped in `refuse` and both tests would still pass.

⚠ **Its first version cut at the midpoint of the blocks and the walk ended cleanly** — correctly, because
the cut happened to land on a block boundary, where a stream that has read whole blocks and then
runs out is simply at the end. The cut is one byte inside the last block now, and the test says
why.

### 3.4 The two sweeps are exhaustive rather than sampled

- **Every truncation is refused**: every byte now, not every sixteenth. A killed writer stops at
  whatever byte the kernel had taken, and a stride of 16 leaves fifteen of every sixteen stopping
  points unvisited — including most of the two- and four-byte fields a section boundary is made of.
  **3,742 cuts, 0.19 s**, against 234 before. The count is asserted, so it cannot go stale.
- **A half-written file still has a header, at every cut** — spec §6.6's whole claim, which nothing
  tested. The boundary is the header's own length: at or past it `read_header` reads, and gives
  back *the same header the whole file does*; below it, it refuses.

## 5. ⚠ What the sweeps found about my own expectations

**The header sweep asserted something false and failed on the first run.** It required a cut inside
the four-byte magic to come back as `NotAnNgPsp`. **0 of 3,136 cuts below the header did**, and the
code is right: the magic is compared only *after* a twelve-byte read of the magic and the declared
body length has succeeded, so a file cut inside its own magic is refused for being too short before
its first four bytes are ever looked at.

**That is the better answer, and the test now says so.** A truncated ng psp is never reported as
the wrong kind of file — *you handed me the wrong file* would send its owner looking for a file
that is not missing.

## 6. Tests added

**Four, and one strengthened.** Every one carries a mutation result rather than an argument.

| test | what it holds |
|---|---|
| `a_writer_killed_before_finishing_leaves_a_file_every_reader_refuses` | a real `SIGKILL` mid-write leaves a file `open` refuses as `Incomplete`, whose header still reads |
| `a_read_that_fails_part_way_through_a_block_is_an_io_error_and_not_damage` | a genuine `EBADF` reaches the caller as `Io`, naming the file and the phrase |
| `a_file_that_ends_inside_a_block_is_damage_and_not_an_io_error` | the contrast that stops the two classes being swappable |
| `a_half_written_file_still_has_a_header_at_every_cut` | spec §6.6 at all 3,742 cuts, with the boundary asserted |
| `every_truncation_of_a_finished_psp_is_refused_without_panicking` | strengthened: every byte, count asserted |

**Three mutations run on the killed-writer test, two killed and one proved to be a no-op:**

| mutation | result |
|---|---|
| the child writes a small sample and **finishes** it before parking | **killed** — `a killed writer cannot have written a footer` |
| the parent kills immediately, before blocks reach disk | **killed** — `the child wrote 0 bytes before the kill` |
| the child calls `finish` *after* its 80,000 pushes | ⚠ **recorded as "changed no behaviour", and that was wrong** |
| the child stops pushing at once and marks that it did | **killed** — `the child stopped pushing of its own accord before the kill` |
| the marker appears while the child is still pushing | **killed** — the same assertion, isolating it from the signal check |

⚠ **The third row was wrong, and it is the worst kind of wrong: I ran the mutation once, saw it
pass, and wrote that down as a property.** The review ran it 40 times standalone — **40 failures**
— and 10 times under the parallel suite, where it passed 3. It was not a no-op; it was a race, and
the race is what the child's rewrite removes. With the child pushing until it is killed there is no
`finish` call in that branch at all, so the mutation is now unreachable rather than inert.

## 8. Trade-offs and follow-ups

- **The killed-writer test is `#[cfg(unix)]`.** `SIGKILL` and `ExitStatusExt::signal` are POSIX;
  there is no Windows equivalent that leaves the same state, and the project's CI is Linux.
- **The child is this test binary.** That couples the test to its own path in the module tree —
  the `--exact` filter names it as a string. ⚠ **This section first said a stale name would fail
  with `the child wrote 0 bytes`. It does not**: a libtest binary whose filter matches nothing
  exits 0, so the *signal* assertion fires first, six lines earlier, and used to say only that a
  destructor had run. Reproduced, and fixed: the child's stderr is piped rather than discarded and
  that assertion now names every cause it cannot tell apart, with the exit code and the child's own
  words.
- **One kill point, not many.** The kill lands wherever the child happens to be. The exhaustive
  truncation sweep is what covers every stopping point; the kill is what proves the mechanism on a
  real process. Neither alone would do.
- **The kill cannot cut inside a block on this fixture**, and the test now asserts that rather than
  claiming the opposite. Reaching a mid-block cut would need one compressed block larger than the
  `BufWriter`'s 8 kB, which this record shape does not produce.
- **`refuse`'s `Io` arm is reached through `walk_from` directly**, not through `PspReader::records`,
  because a `PspReader` opens its own descriptor read-only and there is no way in. The wiring
  between them — `RecordIter::step` calling `refuse` — is shared with every other arm, all of
  which are covered end to end.
