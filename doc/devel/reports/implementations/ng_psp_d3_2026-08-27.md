## 1. What the step is

**Pull decompressed bytes into a rolling buffer, parse a record, hand it over, keep nothing.**
`BlockStream` reads forward over a run of compressed blocks and yields one record at a time, and
what it holds is two 16 kB buffers, zstd's decoder, and where it is in the current block —
**none of it a function of the block size, the read depth, or the length of the genome**.

**Two conditions make a reader cheap and only the first is the compressor's doing** (spec §5.1).
One: do not inflate the whole block. Two: **do not accumulate what you inflated.** Satisfying only
the first moves the memory rather than removing it — in production's cohort run the assembled
per-sample columns are the largest single mass of the heap, larger than the decompression buffers
they came from. §4 below is about the second, because it is the one that gets lost.

## 2. Decisions taken here

### 2.1 It reads from anything, and knows nothing about files

`BlockStream::new(source, manifest)` takes any `Read` and reads forward from wherever it is
positioned. Milestone F's index turns a coordinate into a byte offset and seeks before handing
the source over; nothing here opens a file, which is what lets a test start a reader at an
arbitrary block — and that is D5's whole oracle, available a step early.

### 2.2 The manifest configures the reader, and is destructured exhaustively

The decoder's window comes from the manifest and nowhere else: zstd refuses a frame whose window
exceeds what its decoder was configured for, so a reader that assumed a value would reject a
perfectly good file with an error naming a zstd code (spec §4.2). The record layout comes from
the same place, so a file this build cannot read is refused once, at the reader, rather than
block by block. Both are read out of a `let Manifest { .. }` with no `..`, for the reason D1 and
D2 give: a field a reader must honour is then a compile error here.

### 2.3 The per-block state is a struct, and the reset is one assignment

**This is D1's lesson applied a second time.** Spec §3.2 requires every running difference inside
a block to restart, Milestone E adds the chain-id live set, and a field added beside a reader's
per-block fields and initialised once is one that silently never resets. `BlockCursor` holds the
five — the block head, the records still due, the coordinate offsets are measured from, the
compressed bytes still due, and whether the frame is finished — and `begin_next_block` replaces
it whole. Measured: adding a field to `BlockCursor` is `error[E0063]: missing field … in
initializer of BlockCursor`.

### 2.4 The skip is the caller's predicate, not a second call

`next_record_where` hands the caller each record's head and takes a yes or no. A record declined
costs its head and a pointer advance; its body is never decoded. **What it does not save is
decompression** — a block comes out of zstd sequentially and there is nothing to seek past — so
the saving is the record objects, which spec §4.3 measures as 0.137 s of a 0.30 s walk.

### 2.5 A record's `Truncated` is answered here, and becomes damage only at the block's end

Inside the reader, a record that stops early means *decompress more of this block and try again*.
It becomes `RecordRunsPastItsBlock` only when the block has nothing left to give, because at that
point no quantity of further bytes changes the answer — the same conversion `record.rs` makes for
a field inside a bounded body, one level up. **This is the class split the C2 review's Blocker was
about**, and `PspReadError::CorruptBlock`'s written warning is what it exists to honour.

### 2.6 Still one file

[The D2 review](../reviews/ng_psp_d2_2026-08-27.md) recorded that the `block/` directory split was
deferred to D3. Revisited and **still not done**: `module_structure` **did not object** at D2 — and
at D3 it said so on its own terms: arch §1 assigns all three concerns to this file verbatim, the
checklist has no line-count rule, and its one directory rule points the other way. Also:
`record.rs` is 4,222 lines with its tests against `block.rs`'s 3,915 — closer than at D2, and still the smaller of the two. **⚠ That premise has since flipped**: at the end of Milestone D `block.rs` is 5,270 lines against `record.rs`'s 4,229, the larger by a thousand. The deferral stands on the two *structural* premises alone — arch §1 assigns all three concerns to this file verbatim, and the checklist's one directory rule points the other way — and `module_structure` filed no findings at D4/D5. The seam a split would cut
along is now visible — cut, compress, stream — and is worth taking when a fourth concern arrives
or when someone is changing one of the three anyway, not as a 3,000-line move inside a
feature commit.

Seventeen new ones, taking `ng::psp::block` from 49 to 66 and `ng::psp` to 182.

| test | the defect it exists for |

| `a_file_cut_short_anywhere_inside_a_block_is_refused` | a killed run looking like a sample covering less of the genome — every cut of the file, one at a time |
| `a_block_whose_record_count_disagrees_with_its_records_is_refused` | the count not doing its job in either direction |
| `a_record_that_runs_past_its_block_is_damage_and_not_a_retry` | a reader that asks for more bytes for ever |
| `a_stream_that_refuses_yields_nothing_afterwards` | a refusal that repeats, or a record built from state a refusal left half-advanced — over all four ways to refuse |

## 4. The property the module could not see, and now can

**The line that makes the rolling buffer roll was asserted by nothing.** `pump` drops what the
parser has consumed before asking for more; remove it and every one of the other sixteen tests
stays green while the buffer grows to hold the whole block. That is exactly the half spec §5.1
says gets lost — *"a reader that streams a block in perfectly and then gathers every record into
an array before returning has achieved nothing"* — and it is the memory the whole format exists
to remove.

`a_reader_holds_its_two_buffers_and_never_the_block` reads a file whose largest block is
**several times** the rolling buffer and asserts the reader never holds more than
`READ_CHUNK_BYTES + ROLLING_BYTES`. `BlockStream::buffered_bytes` is what it asks, and it is
public because Milestone H4 measures the same number against the 500 kB per-open-sample budget.

| the decoder is not reset between blocks | **⚠ 0, and the claim was false when written.** Removing it changed the outcome on 11,664 of 60,000 damaged inputs — all of them *after* a first refusal, which is exactly the states §6 called unreachable. ## 6. One line that is defensive, and says so

*⚠ This section was right about the line and wrong about why. It is defensive **because a refused
stream ends**, and at the time this was written one did not — see §5's corrected row and
[the fix report](../reviews/fixes_applied_ng_psp_d3_2026-08-27.md) §4.*

`begin_next_block` resets zstd's decoder. **Measured: removing it passes every test in the
module** — zstd takes consecutive frames on one context without being told, and the only states a
reset would rescue are ones where the previous frame ended mid-way, which already end the stream.
It is kept because a block boundary is where a reader's state resets, and leaving the decoder's
out of that reset would make the exception the thing a later coder has to remember. The code says
this rather than implying the line is load-bearing.

## 8. What D4 and D5 inherit

- **The retry loop exists and D4's property is what it is checked against.** A record that
  straddles the rolling buffer is already retried from its first byte against state the retry arm
  does not touch. D4 owes the oracle — a decode forced to refill at *every* possible boundary —
  and the growth path already has one test rather than the many that class needs.
- **D5's oracle is already here in one form.**
  `a_reader_starting_at_a_block_gets_the_tail_of_a_full_read` walks from every block offset and
  compares against the tail of a full read. What D5 owes on top is the same over a file where the
  running differences have somewhere to go wrong — and Milestone E is what will put them there.
- **`buffered_bytes`** is the number H4 measures against the 500 kB budget.
