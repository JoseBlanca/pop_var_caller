## 1. Plan

**A block ends when a position crosses into the next multiple of `genomic_block_size_bp`, and never
crosses a contig. The optional byte ceiling closes one early.** The new file is
[`src/ng/psp/block.rs`](../../../../src/ng/psp/block.rs), which the architecture document assigns
"the psp block: cutting it, compressing it, streaming it back". This step is the first of the three.

What it adds: `BlockHead` (a block's opening three fields, encoded and decoded), `BlockRecords`
(one whole payload split into its head and its records), `BlockBuilder` (records in, block payloads
out) and `BlockWriteError`. Nothing compresses and nothing writes a file.

## 2. Decisions taken here, and what they depart from

### 2.1 The block head is a type, with both halves, in this step

Spec §3.2 says a block "opens with its chromosome, its first position and its record count" and
does not say how. It is `BlockHead`, three LEB128 integers, **inside** the unit that gets
compressed rather than in front of it — a block whose opening facts lived outside its own bytes
would not be self-contained, which is the property the whole restart guarantee rests on.

**The decoder is here too, though a reader is nominally D3's.** Without it, D1's only oracle would
be the builder checked against itself. With it, every test below walks a block back from its
*declared* first position — which is all a reader starting at that block would have — and compares
against records built independently of the codec.

**Three fields and no fourth.** The measuring prototype's block framing carries the uncompressed
length as well; this does not, and deliberately: spec §8 lists "a block header that carries its
uncompressed length is a temptation to allocate it" among the traps, and the whole design is that a
reader never sizes a buffer from a block.

**The names are `contig-id`, `first-position`, `record-count`** — declared as constants so the name
a refusal reports cannot drift from the name this file uses, which is the idiom `record.rs` settled
on. **They are not manifest fields**: the manifest declares how a *record's* fields are encoded
(spec §4.5), and a block's framing is fixed by the format version the way the file header's magic
is. `a_block_head_is_these_exact_bytes` is therefore the only thing that pins the layout, and a
change to it is a version bump.

### 2.2 Coordinate order is enforced by the builder, not by the record encoder

`RecordEncoder` refuses a record starting before the base its offset is measured from. **That base
resets at every cut**, so a record going backwards far enough to land in an earlier grid cell opens
a new block and is written without complaint — the cut *launders* the very thing the encoder's check
exists to catch. `a_record_that_goes_backwards_across_a_grid_cell_is_refused` is that case, and
dropping the builder's check makes it and three others fail.

Two rules, and the second is not stated in the spec or the architecture:

- **Within a contig, a record must not start before the record before it.** Two records starting on
  the same base are accepted — a repeat tract and a generic locus can begin together.
- **Contigs are visited in ascending order and never revisited.** Derived rather than quoted: spec
  §3.3 says the block index holds "one entry per block, in genomic order", and a contig visited
  twice gives two runs of blocks a seek cannot choose between. Recorded here because it is a rule
  this step invented.

### 2.3 A refused record leaves the builder exactly as it was

`RecordEncoder::encode_record` promises that "`out` is untouched unless the record is written". The
builder keeps the same promise across the cut, which takes an extra buffer to do: a record arriving
at a block boundary is encoded into the buffer that will *become* the new block's, and the old block
is only closed once that has succeeded. A record the codec refuses — an empty region, one at the
coordinate ceiling — therefore leaves the open block open and the encoder's base where it was.

`a_refused_record_changes_nothing_a_later_record_can_see` offers three refusals before every record
of an eight-record run and compares the bytes against the same run without them. Dropping the
one-line rollback fails it and nothing else, so it is the only thing holding that line.

### 2.4 `finish` consumes the builder

**Measured: with `finish(&mut self)`, deleting the line that emptied the record buffer left all
twenty-one tests green** — because nothing in the suite pushed a record after closing. The defect it
hides is a whole block's records appearing again inside the next block. Consuming the builder makes
both that and closing twice unwriteable, which is what arch §4.2 argues for `PspWriter::finish` and
the same argument applies one level down. It returns owned bytes where `push` lends them: once per
file, against a borrow per block.

### 2.5 The block's records are copied once, at close

A block head carries the record count, which is only known when the block closes, so the records
accumulate in one buffer and are copied in behind the head into another. One memory copy of the
block per block, against a zstd level-9 compression of the same bytes immediately afterwards.
Unmeasured, and named here so it is a known cost rather than a discovery.

### 2.6 Not built: accumulating across empty spans

Spec §4.1 offers **two** secondary rules — the byte ceiling, and "keep accumulating across empty
spans rather than emitting near-empty blocks". Only the first is here. The second has no field in
`Manifest` to travel in (arch §3.2 gives it none) and the plan's D1 does not list it.

**⚠ This paragraph originally read spec §12 question 3 as leaving the rule itself open, and it
does not** (the review). It says the rule **ships**, and leaves only *what threshold it uses*
open — so not building it was a departure from the spec, and it was raised with the owner rather
than settled here.

**⛦ Settled 2026-08-27: the rule is dropped, not deferred.** The owner ruled against merging
near-empty blocks because **it would complicate the alignment between samples** — which is the
one property the coordinate grid exists to give, since a merged block may begin ninety cells
before its neighbour's and a cohort reader would no longer know that one block per sample holds a
given position. Spec §4.1 and §12 question 3 need correcting when that document is next touched.
*Not to be confused with the narrower thing, which was always true: a grid cell holding no
records produces no block at all, and `a_grid_cell_with_no_records_produces_no_block` now says
so.* **What it costs to omit is measured in the spec
itself:** on a sample with 74,623 covered positions scattered over 644 regions, a 5 kb grid costs
18.242 bytes a record against 16.444 at 1,000 kb — about 10 %. At the 100 kb default it is 17.557.
So this is a patchy-coverage penalty, not a defect, and it is bounded.

## 3. What the tests are, and what they would catch

Twenty-one tests in `ng::psp::block`. The load-bearing ones:

| test | the defect it exists for |
|---|---|
| `the_cut_is_a_grid_on_the_coordinate_and_not_a_running_total` | records 99,998 bases apart share a block, records one base apart across the multiple do not |
| `two_samples_with_different_records_cut_at_the_same_grid_cells` | a dense sample and a sparse one over the same region give blocks in the same cells. **⚠ As written at D1 this row claimed more than the fixture delivered** — both samples were built from span-1 records, so the mutation that genuinely desynchronises two samples passed it. The review's Blocker; the fix commit gives the sparse sample a record widened across a multiple |
| `a_block_never_crosses_a_contig_even_inside_one_grid_cell` | a reader starting at a block cannot learn its chromosome |
| `every_record_comes_back_once_and_in_order_however_the_blocks_fell` | 63 records over three contigs and three cells each, with a ceiling that fires inside them |
| `a_record_that_goes_backwards_across_a_grid_cell_is_refused` | the cut laundering an out-of-order record |
| `a_refused_record_changes_nothing_a_later_record_can_see` | a refusal that half-closes a block |
| `a_block_head_cut_short_is_truncated_at_every_cut_and_never_malformed` | the class a streaming reader retries on |
| `a_block_head_is_these_exact_bytes` | the framing changing without a version bump |

**Two of the oracles were wrong on their first run, and both were my own claims about my own
fixtures.** `two_samples_…` asserted three grid cells where the fixture reached two (40 records at
1,000 bp from 90,000 stop at 129,000). `every_record_comes_back_…` asserted that a 200-byte ceiling
would fire and it never did — the records are smaller than that. The second is now derived from the
blocks the grid alone produces rather than guessed: the ceiling is a third of the smallest block's
record bytes, so it must fire whatever a record turns out to cost.

## 6. What D2 inherits

- **A block payload is what a compressor is handed.** `BlockBuilder::push` hands one back; nothing
  about it is a function of how it will be compressed.
- **The measurement D2 owes** — the head's four fields fixed-width against variable-length,
  compared after compression — needs this and a compressor, and neither existed before.
- **`BlockRecords::split`** is how a test that decompressed a whole block walks it back.
