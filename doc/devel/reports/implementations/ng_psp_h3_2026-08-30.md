# ng psp store — H3: worker-count invariance

*Implementation report, 2026-08-30. Step H3 of
[`../../ng/impl_plan/psp_file_format.md`](../../ng/impl_plan/psp_file_format.md), branch
`ng-psp-encoding`. Design authority: [spec §7, §4.1](../../ng/spec/psp_file_format.md).*

---

## 1. What the step is

Spec §7: *the block cut is a function of the coordinate and the observation stream alone, so the
same sample gathered at any worker count gives the same file apart from any timestamp in the
header.*

Two halves, and **the second had nothing holding it at all**: what the timestamp being allowed to
differ actually costs.

## 2. ⚠ What this can and cannot prove, before the results

**ng's writer is serial.** It is handed records in coordinate order, and what a run parallelises is
the *producing*. So "byte-identical across worker counts" rests on two things, and only one of them
is `psp/`'s doing:

1. **the writer is a function of the record sequence alone** — nothing about *when* records arrive
   reaches the bytes. That half was already held, by `the_same_records_written_twice_give_the_same_bytes`
   (F3), which is where a leaked timestamp, a hash iteration order or an address would show;
2. **the sharding gives back the same sequence** whatever the worker count. That is the run's job,
   reproduced here so the claim is end to end rather than assumed.

**Saying so matters, because with respect to the worker count the file comparison is not close to
a tautology — it is exactly one.** The review made that precise: `SampleLocusObservations` carries
no float, so record equality is structural equality of everything the writer reads, and nothing
about the worker count survives past the sequence assert.

⚠ **But the sentence "no mutation kills the file comparison and not one of the others" was wrong,
and the review disproved it.** A writer nondeterminism gated at sixteen blocks — F3's fixture cuts
**8**, this one cuts **40** — passed F3 and passed the sequence assert, and the file comparison was
the only thing in 397 psp tests that failed. So what it buys is real: **a second determinism check
on a fixture five times F3's size**, which is where a nondeterminism needing a long index would
show.

⚠ **And "the run's job, reproduced here so the claim is end to end" overstated what exists.**
There is no production per-sample sharding in `src/ng/` — `src/ng/run/` holds only `cohort_merge`,
a different stage. `a_sample_gathered_by` is a twenty-line stand-in written in this same test. It
is the shape the run will have to satisfy, not a check on the run.

## 3. Decisions taken here

### 3.1 The workers are real threads, and the shards are deliberately uneven

`std::thread::scope`, one thread per shard, at 1, 2, 4, 8 and 16 — so the interleaving in time
genuinely varies. What must not vary is the sequence that comes out.

⚠ **The first version's shards split exactly on the grid, and the test refused itself.** Two equal
contigs split evenly put the two-worker boundary on the second contig's first record — a grid line
— and the four-worker boundaries on grid lines too, since 250 records at 40 bases is 10,000, a
whole number of 1 kb cells. **A sweep whose every shard boundary sits on a grid line cannot tell a
cut that follows the coordinate from one that follows the shards**, which is the only thing it is
for. The split is skewed now, and the count of boundaries falling *inside* a block is asserted per
worker count rather than hoped for.

### 3.2 The timestamp half is its own test, and it is about width

`two_runs_differing_only_in_their_timestamp_differ_only_inside_the_header` writes the same records
twice with two stamps and requires **every differing byte to lie inside the header**.

**The hazard is the rendered width.** The stamp goes into the header's TOML, so a stamp one
character wider moves the header's length — and with it every offset in the footer, the index, and
the blocks' positions. A run whose files differed past the header is one where nothing downstream
can compare two samples byte for byte, which is what §7 offers.

## 5. Tests added

**Two**, and a third cited rather than duplicated: writing my own determinism test failed to
compile because `the_same_records_written_twice_give_the_same_bytes` already exists. It is cited
from the new one's doc instead, which is the better outcome — one claim, one test.

**Two mutations run, two killed** — and the review then ran nine, of which one survived (§8).

| mutation | result |
|---|---|
| the shards split evenly, so every boundary lands on a grid line | **killed** — `at 2 workers every shard boundary lands on a grid line` |
| every shard but the first drops its last record | **killed** — `at 2 workers the sharding produced a different number of records` |

The first is not hypothetical: it is how the test was first written, and it refused itself on the
first run.

⚠ **This section first said "three mutations, three killed" over a table holding two**, the third
row being a `—` recording the *absence* of a mutation. The count is the headline evidence that
these tests can fail, and getting it wrong costs trust for nothing. The same wrong figure went into
the commit message and `PROJECT_STATUS.md`.

## 8. ⚠ What the review found, and what is raised rather than taken

**One mutation survived: the mid-block precondition hardcoded the grid.** It filtered boundaries by
`(position - 1) % 1_000 != 0` while the grid was supplied separately as `a_header(1_000)`, and the
two literals had to agree with nothing making them. Reproduced here before the fix: writing the
fixture on a **40 bp** grid gives every record its own block — 1,000 instead of 40 — so **every**
shard boundary lands on a grid line, the exact condition the assertion exists to refuse, and the
test still passed. One named constant, `GRID_BP_OF_THE_SHARDED_SAMPLE`, now drives both ends, and
the same mutation fails.

**And spec §7's byte-identity holds only while every stamp renders to the same width — which
nothing enforces.** `created` is a `toml::value::Datetime`, so `2026-08-30T11:22:33.5Z` is two
characters wider than `2026-08-28T00:00:00Z`; measured, the file grows by exactly two bytes and
every offset past the header moves. ng has no production header writer yet, and a future `pileup`
using `to_rfc3339` — which prints sub-second digits only when non-zero — would produce stamps of
varying width run to run.

**A test pins that limit rather than the promise.** It was raised to the owner, who ruled on
2026-08-30 **not to chase it**: differences due to timestamps are not worth spending the format's
contract on. So nothing in the writer changes and §7 keeps its wording; the test stays as the
record of where the promise stops, which is the cheap half of the fix and the half worth having.

Also taken from the review: worker counts that do **not** divide the record count (3, 5, 7) now run,
so the truncating branch is exercised with a remainder; `shard_boundaries` is tested with more
workers than records, the case its `.min` and `.dedup` exist for; the three copies of *write a
sample* are one; and the block-count message no longer claims a relation that does not hold.

## 7. Trade-offs and follow-ups

- **Five worker counts, one sample shape.** The records are uniform; a real run's shards differ in
  how many records they hold. What the test covers is that the *boundaries* do not reach the file.
- **The invariance is not tested across machines or zstd versions.** Byte-identity depends on the
  compressor being deterministic at a fixed level, which it is within a build, and the header
  records the level (F3) so a file written by another build says so.
