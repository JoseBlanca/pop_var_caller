## 1. The step, and the collision it resolves

**Two things the format wants, and they pull against each other.**

A reader may **skip a record's body** without decoding it — that is what the record head's byte
count is for, and spec §2.3 measures the walk it buys at 2.06× faster. And the chain ids are stored
as **changes**: which reads started covering a record and which stopped, with the reader carrying
the set forward, which is what takes the column from 43.78 bytes a position to 6.42 at three
hundred reads.

**A reader that skipped a record's body would never see that record's changes.** Its set would go
stale, and every later record it *did* want would be wrong — silently, because a stale set is still
a plausible set, and the cohort merge would compose an allele for a read that was not there.

**The resolution splits the column across the skip** (spec §6, arch §5): the live-set changes go in
the **head**, where every reader decodes them whether or not it wants the record; the exception
lists — the ids of every observation except the residual one — stay in the skippable **body**,
because they carry no state. This step builds the first half. The second is E4's.

## 2. Decisions taken here

### 2.1 A fifth head field, and a composite in an otherwise scalar set

`RECORD_HEAD_FIELDS` gains `("chain-id-changes", FieldEncoding::ChainIdChanges)`, written between
the body's byte count and the body itself — so `body_bytes` does not reach it and a reader that
skips the body has already decoded it.

**`FieldEncoding` was a closed set of scalars, and this is the first composite.** The set exists so
a reader can *measure* a field a later writer added and walk past it; this one can be measured —
two counted runs of varints — but **cannot be walked past by anybody**, because it carries the
state every later record is decoded against. It is a named scheme rather than an opaque byte run
for exactly that reason: the name makes a file that carries it refuse an older reader, instead of
that reader stepping over the field and building every record after it against a stale set.

### 2.2 Starting a block is a different method, not a call to remember

E2's report named the hazard E3 inherits: *a writer that forgets to reset at a block boundary
produces a file that parses perfectly and is wrong from that block's first record, because the
reader restarts whether the writer did or not.*

**`RecordEncoder::start_block` is gone.** In its place,
`encode_record_starting_a_block(record, out)` is the only way to open a block, and it resets both
running differences itself. There is no call to forget, because starting a block and writing its
first record are one operation.

### 2.3 ⚠ And a reset is not undoable, which changed the writer's shape

`BlockBuilder`'s cut path used to reset the encoder to the new block, try the record, and — if the
codec refused it — put the coordinate base back with a second `start_block(resume_at)`, leaving the
open block open.

**A coordinate base can be put back. A live set cannot**, and the open block still needed it. So
`encode_record_starting_a_block` makes every refusal *before* it resets anything: the refusals
depend on the record alone — a region covering no base, a span past the coordinate axis, a body
larger than its own length field — and none of them on either running difference. The rollback is
gone rather than extended, and `a_refusal_at_a_cut_leaves_the_open_blocks_live_reads_alone` is what
holds it.

### 2.4 The head is read once, and the body is built from what it located

Reading a head now **applies** that record's changes, so parsing a record twice would apply them
twice — and the second time an arriving read is already live, which this codec calls damage. So
`decode_record` splits: `read_record_head` locates the record and moves the set,
`decode_the_body_of` takes what the head found. The streaming reader calls each once.

## 3. What the tests are

Three new in `ng::psp::block`, and every existing test in `record.rs` and `block.rs` now carries a
live-set reader across the records it walks.

| test | the defect it exists for |
|---|---|
| `a_walk_that_skips_almost_every_body_knows_which_reads_are_live` | **the step's whole reason** — §4 |
| `a_skipping_walk_from_any_block_has_the_reads_a_full_walk_has_there` | Milestone F's index hands a reader a block offset and nothing else; the restart and the skip have to hold together |
| `a_refusal_at_a_cut_leaves_the_open_blocks_live_reads_alone` | §2.3's hazard, which this step created and the writer's new shape removes |

## 4. The oracle

**A walk that declines six records in seven must have, at each record it does take, exactly the
reads a walk that built every record has there.**

The fixture is paired-end coverage — 300 records, two pairs starting at each position, mates twelve
bases with a nine-base hole — cut into several blocks, so the set restarts inside the walk as well.
Both halves of the assertion are checked rather than assumed: that the fixture actually puts reads
live (more than twenty at once), and that the walk actually skips (fewer than one record in six
built).

**Written the obvious way this test could not fail.** A reader and a writer that both kept the
changes in the body agree with each other; what separates them is comparing the *skipping* walk
against the *full* one over the same bytes, which is what this does.

## 5. Falsification — four defects injected

| defect injected | tests failed |
|---|---|
| **the changes reach the reader only when it wants the record** — the defect the head placement exists to prevent | 2 |
| the writer resets the coordinate at a block but not the live set | 2 |
| the reader does not reset the live set at a block | 2 |
| the body is decoded by parsing the head a second time, applying the changes twice | 2 |
| **the reset happens before the refusal**, as the writer used to be shaped | 2 |

Five for five.

## 7. What E4 inherits

- **The exception lists are the body's half, and they are not written yet.** `encode_record_body`
  still drops `SequenceObservation::chain_ids`; what this step writes is the live set's changes,
  which are the *union* of what a record names. E4 writes each observation's own list except the
  residual one's, and derives that one as the live set minus the others.
- **The count check spec `psp_chain_id_encoding.md` §5 names is the guard**: a derived list is at
  most its observation's read count and at least half of it, since at most two mates share an id.
- **Two classes of read are counted and never named** — `reads_without_observation` and
  `reads_discarded_by_cap` — and neither may leak into the residual. A read the depth cap discarded
  is in no observation, so if it is in the live set the residual gains an id nobody folded.
