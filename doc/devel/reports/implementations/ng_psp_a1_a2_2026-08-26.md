# ng psp store — A1 and A2: the vocabulary, and a header that round-trips

*Implementation report, 2026-08-26. Steps A1 and A2 of
[`../../ng/impl_plan/psp_file_format.md`](../../ng/impl_plan/psp_file_format.md), branch
`ng-psp-encoding`. Design authority: [`../../ng/arch/psp_file_format.md`](../../ng/arch/psp_file_format.md)
(the types) and [`../../ng/spec/psp_file_format.md`](../../ng/spec/psp_file_format.md) §3.1 (the
header).*

## 1. Plan

**A1 and A2 ran as one loop iteration, and that is a deliberate departure the plan allows.** A1 is
declarations with no function bodies — the plan's own "pure-scaffold step" — so reviewing it alone
would have had nothing to mutate. A2 is the first code that does anything, and it is the code A1's
types exist for. They are committed together, named as two steps in one commit.

A3 (`read_header` from a file, and refusal of a bad one) stays its own iteration: it is file I/O with
its own fixtures.

What landed:

- `src/ng/psp/` — the module, five files of the seven [arch §1](../../ng/arch/psp_file_format.md)
  names. `block.rs` and `chain_ids.rs` arrive with Milestones D and E; empty files now would be
  noise.
- **A1** — `RecordHead`, `Header`, `Manifest`, `FieldSpec`, `FieldName`, `FieldEncoding`,
  `ContigEntry`, `ReferenceIdentity`, `WriterProvenance`, `ParameterValue`, `BlockIndexEntry`,
  `Footer`, `PspReadError`, `PspWriteError`.
- **A2** — `Header::encode`, `Header::decode`, the framing constants, and one set of validation
  rules checked from both sides.

## 2. Assumptions and departures

**Nine choices the design documents left open or stated in a way the real code could not carry.**
Each is a place a reader of the arch doc would expect something else.

### 2.1 `Header.reference` is a name and a digest, not `ReferenceInfo`

[Arch §3.2](../../ng/arch/psp_file_format.md) writes `pub reference: ReferenceInfo` beside
`pub contigs: Vec<ContigEntry>`. The only `ReferenceInfo` in the crate
([`src/ng/reference_info.rs:71`](../../../../src/ng/reference_info.rs)) is the whole description of a
reference on disk: it holds every contig's `.fai` geometry — the byte offset of its first base, its
line width — and the FASTA's absolute path. Two things follow, and the second is decisive:

- it duplicates the contig list, since `ReferenceInfo.contigs` *is* that list with extra fields;
- **it cannot round-trip.** A psp has no reason to store `.fai` geometry, so a parsed header would
  have to invent it — and a `ContigInfo` with `line_bases == 0` is a shape that type's own
  documentation calls illegal. Storing the path instead would put the producer's directory layout in
  every file that is ever shared.

So `reference` is a `ReferenceIdentity { name, md5 }` — the reference's basename and the
whole-assembly digest — which is what [spec §6.6](../../ng/spec/psp_file_format.md)'s use for
`read_header` actually needs: checking that a cohort's files agree on a reference before a run
commits to them. The contig list stays its own field.

### 2.2 The header mints its own `ContigEntry`

[`crate::fasta::ContigEntry`](../../../../src/fasta/mod.rs) has the right three fields and a
hand-written `PartialEq` that **treats an absent MD5 as a wildcard**: `Some(digest) == None` is
`true` there. A round-trip test written against that type would pass while the encoder dropped every
digest in the file. The header's `ContigEntry` is the same three fields with derived equality.
`header::tests::a_dropped_contig_md5_is_a_difference_here_and_a_wildcard_in_the_fasta_type` asserts
both halves, so the reason survives whoever next wonders why there are two.

### 2.3 `BlockIndexEntry` carries one position, not a contig beside one

[Arch §3.4](../../ng/arch/psp_file_format.md) lists `contig: ContigId` *and*
`first_position: GenomePosition`, and `GenomePosition` is that pair. One field, because its derived
ordering is contig-then-position, which is the key the coordinate lookup of G1 will search on.

### 2.4 A fifth read error: `MalformedHeader`

[Spec §6.7](../../ng/spec/psp_file_format.md) tabulates four read-side classes and a broken header is
none of them. Production distinguishes about a dozen header faults
([`src/psp/errors.rs`](../../../../src/psp/errors.rs): `BadHeadMagic`, `BadHeaderLength`,
`HeaderToml`, `SentinelMismatch`, `InvalidHeaderField`). They are one variant here with a `reason`
string, because arch §4.3's rule for splitting variants is that the instruction differs, and every
one of these says *the file is damaged, rebuild it*.

### 2.5 The magic is `NGP\n`, not production's `PSP\n`

Both formats use the extension `.psp` and both will sit on the same disks while ng is built, so the
first four bytes are what tells them apart. Sharing the magic would leave the two to disagree later,
over the TOML body, with an error naming a missing key rather than the wrong format. Printable with
the newline last, so `head` still opens the body on a following line —
[arch §6](../../ng/arch/psp_file_format.md)'s reason for keeping production's framing.

### 2.6 `WriterProvenance` is ng's own, and it carries the timestamp

Production's is in the frozen tree, and ng copies rather than imports (`src/ng/mod.rs`). Its fields
are production's, renamed for ng's vocabulary: `input_alignments` (ng reads BAM and CRAM),
`input_reference`. **`created` sits here rather than on `Header`**, so that everything which
legitimately differs between two otherwise identical runs is in one field — which is what H3's
worker-count byte-identity check has to exempt ([spec §7](../../ng/spec/psp_file_format.md)).

### 2.7 `FieldName` is a string, not a closed set

[Spec §4.5](../../ng/spec/psp_file_format.md) says a reader should be able to skip a field it does
not recognise. A closed enum cannot represent one. It is a newtype so a field's name cannot be passed
where a sample's or a contig's is wanted.

### 2.8 `FieldSpec` has no cardinality

[Spec §4.5](../../ng/spec/psp_file_format.md) says the manifest carries "its name, its cardinality,
its encoding, and that encoding's parameters"; [arch §3.2](../../ng/arch/psp_file_format.md)'s
`FieldSpec` has name and encoding only. The arch is followed, because the record codec is written by
hand against a fixed field set (spec §4.6) and knows each field's shape statically. **The cost is
that the skip-an-unknown-field property of §4.5 is not reachable for a list-shaped field**, whose
length a reader cannot measure from the encoding alone. Flagged for Checkpoint A.

### 2.9 `Header::decode` takes the path it is decoding

Every `PspReadError` variant names the file, because that is what makes the message actionable. A
byte-slice decode has no path of its own, so it is passed in and not read.

## 3. Changes made

| file | what |
|---|---|
| [`src/ng/psp/mod.rs`](../../../../src/ng/psp/mod.rs) | the module's own account of the format, the file layout, the three words it uses differently from production's `src/psp/`, and both error enums |
| [`src/ng/psp/header.rs`](../../../../src/ng/psp/header.rs) | `Header` and everything in it; the framing constants; `encode`, `decode`, `version_of`; one set of validation rules; the wire types the TOML body actually is |
| [`src/ng/psp/record.rs`](../../../../src/ng/psp/record.rs) | `RecordHead` |
| [`src/ng/psp/index.rs`](../../../../src/ng/psp/index.rs) | `BlockIndexEntry` |
| [`src/ng/psp/footer.rs`](../../../../src/ng/psp/footer.rs) | `Footer`, `FOOTER_BYTES` |
| [`src/ng/mod.rs`](../../../../src/ng/mod.rs) | `pub mod psp;` |

**Nothing outside `src/ng/` was touched**, and nothing in the frozen production tree.

Two shapes worth naming:

**The validation rules are written once and run from both sides.** `check_rules` returns a broken
rule as a `(field, reason)` pair; the writer dresses it as `InvalidHeaderField` and the reader as
`MalformedHeader`. Two copies of one rule are two things that can disagree — and a writer that
produces files its own reader refuses is the failure that shape prevents.

> **⚠ Corrected 2026-08-26 by [the review](../reviews/ng_psp_a1_a2_2026-08-26.md): as committed,
> the writer *could* produce a header its own reader refused, twice over.** A contig length or a
> block size above `i64::MAX` was serialised by the `toml` crate and then rejected by its own
> parser, and `check_rules` never looked at the magnitude. Separately, the writer's table of
> encoding spellings and the reader's were two independent lists, so a scheme added to one alone
> produced exactly that failure with the suite green. Both are fixed; the property now holds, and
> the two boundary cases and the shared list are each pinned by a test.

**The version is read before the body is interpreted.** `decode` parses the body into a bare
`toml::Table`, takes `format-version` from it, and refuses a differing major as
`UnsupportedVersion` *before* deserialising into this version's types. That is the whole reason the
header is plain text ([spec §3.1](../../ng/spec/psp_file_format.md)): a file written by a newer
format has to say so, not come back as unparseable TOML.

## 4. Tests

**26 tests, all in `#[cfg(test)] mod tests` beside their module.** The counts below are from
`cargo test --lib ng::psp`.

| module | tests | what they pin |
|---|---:|---|
| `header` | 18 | the round trip; the two fixed-point steps staying apart; the body being readable TOML; parameter order not depending on how the map was filled; the version checks; every validation rule, from both sides |
| `mod` | 3 | the error messages spec §6.7 promises, including the numbers whoever sees them must act on |
| `footer` | 2 | the footer's width against production's tail, and that it holds no allocation |
| `record` | 2 | `RecordHead` being `Copy` and small, and carrying a span wider than one base |
| `index` | 1 | entries ordering by contig before position |

**The validation test is one test over fourteen broken headers, checked twice each — 28 refusals.**
For every rule, a header that breaks it is refused by the writer *and*, framed into bytes without the
writer's checks, refused by the reader. The fourteen: an empty sample; a reference recorded with its
directory; no contigs; one contig named twice; a contig of no length; a parameter that is not a
number; a block grid of no width; a byte ceiling no block can stay under; a look-back window zstd
cannot take; no declared fields; one field declared twice; a fixed integer three bytes wide; a
four-byte-or-eight IEEE float declared at two; a fixed-point field counting steps of 1/0.

> **⚠ Corrected 2026-08-26 by [the review](../reviews/ng_psp_a1_a2_2026-08-26.md).** Two claims
> above were wrong about this module's own tests, which is the class of claim this project has
> recorded getting wrong before.
>
> **The table drew fourteen of the rule set's twenty-two rules, not all of them**, and the sentence
> "for every rule" was false. The six it never reached included both provenance rules and both
> contig-name rules; four mutations deleting rules survived the whole suite. **And three of the
> fourteen fixtures sat far past their rule's boundary rather than one step over it**, so widening
> those bounds also survived. The table is now 24 rows with every fixture at its boundary.
>
> **The Blocker was in a claim of §3's, not here**: `decode` returns where the first block begins,
> and every test handed it a buffer that was exactly the header, so returning the buffer's length
> instead passed all 26.

Three tests exist because the failure they catch is silent:

- `two_fixed_point_steps_in_one_manifest_stay_apart` — a manifest holding a step of ¼ of a read and
  one of 1/4,096 of a natural log. A decoder reading the step from the wrong field still produces
  integers.
- `an_encoding_carrying_the_wrong_parameter_is_refused` — `encoding = "varint"` beside
  `scale = 4096`. Read as a plain varint, every value in that field is 4,096× too large.
- `the_same_header_encodes_to_the_same_bytes_whatever_order_it_was_built_in` — goal 5's byte
  identity, which a map with a run-dependent order would break in the header before any record was
  written.

## 6. Tradeoffs and follow-ups

**For Checkpoint A — the six that touch the design**, §2.1 to §2.8 above, of which these are the ones
an owner might overrule rather than merely note:

- `reference` becoming a name and a digest rather than `ReferenceInfo` (§2.1);
- the manifest carrying no cardinality, so an unrecognised *list* field cannot be skipped (§2.8);
- a fifth read-error class the spec's table does not list (§2.4);
- the magic differing from production's (§2.5).

**Deferred, with a home:**

- `block.rs` and `chain_ids.rs` — Milestones D and E.
- The header field [`cohort_merge.md`](../../ng/spec/cohort_merge.md) asks for, the **observation
  reach ceiling**, is routed by [spec §3.1](../../ng/spec/psp_file_format.md) to
  [`run_streaming.md`](../../ng/spec/run_streaming.md) §6.1 and is not added here.
- The widths in `FieldEncoding::Fixed` and `Ieee` are validated (1/2/4/8 and 4/8) but **nothing yet
  chooses them**; arch §7 asks for a measurement at implementation time, which needs a writer.
