# ng psp store — F4: open, and refusal

*Implementation report, 2026-08-28. Step F4 of
[`../../ng/impl_plan/psp_file_format.md`](../../ng/impl_plan/psp_file_format.md), branch
`ng-psp-encoding`. Design authority: [spec §6.2, §6.7](../../ng/spec/psp_file_format.md),
[arch §4.1](../../ng/arch/psp_file_format.md).*

---

## 1. What the step is

**`PspReader::open` — the footer, the index and the header, and no block at all.** That is the
cost a cohort pays per open sample before it reads anything, multiplied by the cohort size, which
is why it is three reads at fixed places rather than a walk.

And the refusals: a file with no valid footer, a file that was never an ng psp, a file whose
sections do not describe it, an index that does not match its checksum, and a look-back window
wider than this reader budgeted for.

## 2. Decisions taken here

### 2.1 A killed writer and a foreign file are told apart, and the head magic is what does it

Both lack the tail magic. Only one can be fixed by re-running the pileup.

So when the footer's magic is wrong, `open` reads the file's **first** four bytes: not this
format's head magic means `NotAnNgPsp`, and anything else means `Incomplete`. **The extra read is
only on the failure path**, so an ordinary open pays nothing for it. The everyday wrong file is
production's own `.psp`, which shares the extension and nothing else.

### 2.2 What `open` checks that the footer could not

`decode_footer` deliberately checks only what 48 bytes can check about themselves (F2 §2.1).
`open` knows the file's length, so it adds the three that need it:

- **the trailer must end exactly where the footer begins** — a file whose sections stop short has
  bytes nothing accounts for, and one that runs past has sections overlapping the footer;
- **the index must not start inside the header**;
- **every block offset must land in the blocks**, which end where the index begins — an offset is
  where a reader would seek, and seeking into the index would decompress the index.

### 2.3 The checksum before the decode

A flipped bit inside a block offset gives a **perfectly well-formed index pointing somewhere
else**. Nothing but the checksum can see that, so it is verified before `decode_index` is called
rather than after.

### 2.4 The window budget is derived from the spec's own numbers

`DEFAULT_LOOK_BACK_WINDOW_BUDGET_BYTES` is **2^18 = 256 kB**. Spec §7 puts an open file at 227 to
346 kB against a budget of 500 kB; §5.3 puts zstd's context at about 190 kB and the reader's two
buffers at 16 kB each. That leaves roughly 278 kB for the window, and 2^18 is the largest power of
two under it. It is **eight times the 32 kB this build's writer produces**, so an ordinary psp
opens with room.

**⚠ That is arithmetic on the spec's figures, not a measurement of this reader**, and it is
written on the constant. Milestone H4 measures what an open sample costs and is where the number
is confirmed or moved.

It is a knob because spec §4.2 makes the fix for a too-wide window *a setting rather than a
rebuilt file*, and the refusal names both numbers so an operator can act on it.

### 2.5 One damage class, not one per rule

`PspReadError::Damaged` carries a reason rather than splitting into a variant per broken rule.
They share an instruction — the file is damaged, rebuild it — and it is deliberately *not*
`Incomplete`, which means a writer was killed and re-running fixes it. That is the same reasoning
`MalformedHeader` already follows.

### 2.6 The header is read with `read_header`

Reuse over rewrite: `read_header` is A3's, already reviewed and hardened against a length that
sizes a buffer before it is believed. It opens the file a second time, which costs a file
descriptor transiently and no resident memory — and the budget this format is shaped around is
resident bytes.

## 4. Tests added

Fifteen. The two that carry the most:

**`opening_touches_no_block`** — spec §6.2's central property, **shown rather than asserted**:
every byte of the blocks region is overwritten with `0xA5`, and the file still opens and still
reports the same header, the same block list and the same trailer. A reader that decompressed
anything at open would fail here.

**`a_file_with_no_footer_is_refused_as_incomplete`** — goal 3. The file is not empty; it holds a
header and blocks, which is exactly why reading it short would be so easy and so wrong.

The rest: the header, blocks and trailer come back and the blocks are in genomic order; a file
shorter than a footer is refused at 0, 1 and 47 bytes without panicking on the subtraction that
finds the footer; a foreign file (production's `PSP\n`) is refused **as foreign**; sections that
do not account for the file, an index that fails its checksum, and an index naming a block outside
the blocks are each `Damaged`; a window of 4 MiB is refused naming both numbers **and opens when
the budget is raised**, which is what makes the refusal a setting; the window this build writes is
8× inside the default budget; an empty psp opens and an empty trailer reads back empty; a missing
file names itself and what was being done to it; and **every truncation of a finished psp**, at
every sixteenth byte, is refused — all of them as incomplete, since a truncated psp has by
definition lost its footer.

**Ten defects injected, ten caught**, every mutation asserting its anchor matched exactly once
before running:

| defect | caught by |
|---|---|
| a missing footer is read short instead of refused | 2 |
| the index checksum is not checked | 1 |
| the sections-account-for-the-file check is dropped | 1 |
| the block-inside-the-blocks check is dropped | 1 |
| the window budget is not enforced | 1 |
| the window budget is compared the wrong way round | 5 |
| a foreign file is reported as unfinished | 1 |
| the index is read from the wrong offset | 4 |
| the trailer is read from the index's offset | 2 |
| the default budget is raised past every window | 2 |

## 6. Trade-offs and follow-ups

- **`records`, `records_from` and `records_where` are not here** — they are G1 and G2. What `open`
  gives is the header, the block list, the trailer and the footer's offsets, which is what
  `BlockStream` needs to be pointed at a block.
- **The window budget is checked against the header's declaration, not against a frame.** Spec
  §4.2 notes zstd records the window in each frame too, and calls a mismatch between the two "a
  corruption worth detecting rather than tolerating". Nothing detects it yet; that belongs with
  the first code that opens a frame, which is G1's walk.
- **Nothing verifies that a block offset points at a *whole* block** — only that it lands in the
  blocks region. Checking further means reading a block, which is exactly what `open` must not do.
