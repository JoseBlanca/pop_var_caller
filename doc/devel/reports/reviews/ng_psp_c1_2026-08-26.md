## 2. Verdict

**Request-changes.** One Blocker and thirteen Majors, and the Blocker was found independently by
five of the eight categories. **The parse itself came out sound** — no panic, no arithmetic
overflow and no allocation sized by a declared length across 600,492 hostile inputs — so every
finding is about what the tests and the prose claim rather than about what the decoder does with
bad bytes. Three of the diff's own claims were measured **wrong**, and all three are claims the
commit message leads with.

## 4. Open questions and assumptions

1. **Do witness runs that a writer could not have produced get repaired or refused?** (affects B1's
   neighbours, M5.) `WitnessedLocusPositions::from_half_open_runs` sorts and merges, so a body
   declaring `(0,5),(3,9)` decodes into the single run `(0,9)` — a *different valid record*, byte
   count intact, so C2's length check cannot see it either. The C1 report calls the normalisation
   deliberate; nothing in the code says so and nothing tests it. **Resolved in the fixes: refused.**
2. **Does a locus kind added by a later minor version mean "damaged file" or "upgrade the
   reader"?** (M7.) Only the *major* version is enforced at open, and the whole unknown-field
   mechanism exists so a later minor is readable — but an unrecognised kind tag landed in
   `Malformed`. **Resolved in the fixes: a third error class.**
3. **Where do the two new error types fold into `PspReadError` at Milestone D?** (M13.) None of the
   existing variants can carry them without loss: `CorruptBlock`'s `#[source]` is a
   `std::io::Error` and its meaning is *the file is damaged*, which is the wrong instruction for a
   short buffer. **Deferred to D, deliberately** — see §7.

## 5. Top 3 priorities

1. **B1 — nothing pins the on-disk layout.** The commit's headline claim is that the manifest and
   the codec are one list. They are two, and every test derives its expectation from one of them.
   Five categories found it independently.
2. **M1 — a declared length no body could hold is reported as the *retry* signal.** `Truncated` is
   what Milestone D grows its buffer for; a corrupt length of 2⁴⁰ therefore asks a reader for a
   terabyte instead of reporting damage. And no test anywhere pins the split.
3. **M4 — `encode_record_body` reads its fields one at a time**, so a field added to either record
   type is never flagged on the write side, and the neutral value a repaired fixture picks is the
   same one the decoder invents. The two window statistics the format expects to gain are exactly
   this case.

## 6. Findings

### Blocker

**B1: [src/ng/psp/record.rs:103](../../../../src/ng/psp/record.rs#L103) — `BODY_FIELDS` and the codec are two lists that happen to agree, and every test derives its expectation from one of them**
**Categories:** reliability, smells, defaults, refactor_safety, extras — **five, independently.**
**Confidence:** High.

`record_body_fields()` and `RecordBodyLayout::from_manifest` both read `BODY_FIELDS`;
`encode_body` and `decode_body` are hand-written and never mention it. So the 56-manifest test
compares the array with itself, and both halves are free to drift. Six surviving mutations across
four agents, each proved to change what the code produces:

| what was changed | what the suite said |
|---|---|
| `"mapq-sum"` renamed to `"mapq-total"` in the array — the name a written file carries | 22 passed |
| `mapq-sum` / `mapq-sum-of-squares` swapped in the array, codec untouched | 22 passed |
| `mapq-sum` declared an 8-byte fixed-width integer while the codec still writes a varint | 22 passed |
| a 20th entry added to the array that the codec never writes | 22 passed |
| `mapq_sum` / `mapq_sum_sq` swapped in **both** encoder and decoder, array untouched — bytes measurably different | 22 passed |
| `KIND_SSR_BUNDLE` renumbered 2 → 3 on both sides | 22 passed |

**Why it matters:** the manifest is a psp's account of its own bytes, and the format's one defence
against a version mismatch is refusing a file whose fields it does not recognise. If the account
and the bytes can diverge with a green suite, that defence passes while the file is misread — and
the psp is on disk by then. Milestone E is the immediate case: one agent added a per-observation
chain-id list to both halves of the codec, left the array at nineteen entries, and both manifest
tests still passed.

**Fix:** a golden byte-string for the fixture and a golden list of the declared names — the only
two assertions in the module that do not come from the code they test — plus a doc comment that
says what the array is (a fingerprint) rather than what it is not (a codec description).

### Major

**M1: [record.rs:541](../../../../src/ng/psp/record.rs#L541) — a declared length no body could hold is `Truncated`, which is the *retry* signal**
**Categories:** errors. **Confidence:** High.
A body claiming 2⁶⁴−1 reference bases is reported identically to one that stopped a byte early, and
a declared observation count of 2⁶⁴−1 comes back as a truncation of the *next* field. `Truncated`
is what Milestone D4 grows its rolling buffer for. The format already carries the ceiling that
makes these impossible: the head's `body_bytes` is a `u32`.

**M2: [record.rs:286](../../../../src/ng/psp/record.rs#L286) — nothing pins the `Truncated` / `Malformed` split**
**Categories:** errors, reliability, extras. **Confidence:** High.
Every hostile test asserts `is_err()`. Three mutations that swap the two classes — in the varint
decoder's two arms and in `take` — each left the suite green. A wrong `Malformed` makes D reject a
good straddled record; a wrong `Truncated` makes it retry forever on a corrupt one. Measured: all
75 cuts are already `Truncated`, so tightening the assertion costs nothing.

**M3: [record.rs:522](../../../../src/ng/psp/record.rs#L522) — the `u16` narrowing guard has no test**
**Categories:** errors, reliability, idiomatic, extras. **Confidence:** High.
`value as u16` in place of `u16::try_from` survives the whole suite. A declared witness run start of
70,000 then becomes a run at offset 4,464 — a read's evidence at the wrong positions inside the
record, no panic, no error. Its `u32` twin *is* tested, and the same mutation there is killed.

**M4: [record.rs:309](../../../../src/ng/psp/record.rs#L309) — `encode_body` reads fields one at a time, so a field added to either record type is silently dropped**
**Categories:** refactor_safety. **Confidence:** High.
The compiler stops at `decode_body`'s two struct literals and at three test fixtures — but that
forces the author to *name* the new field, not to encode it, and the natural repair at both places
is the same neutral value. Measured twice: `SequenceObservation::reads_clipped_right: u32` repaired
with `0` at 31 sites, and `SampleLocusObservations::window_gc_fraction: f32` repaired with `0.0` at
35 sites, both leaving the suite green; both turn it red at once when the fixture gets a non-neutral
value. **The window's GC fraction is one of the two fields this record is expected to gain.**

**M5: [record.rs:549](../../../../src/ng/psp/record.rs#L549) — witness runs a writer could not have produced are silently rewritten into a different witness**
**Categories:** errors, reliability. **Confidence:** High.
`(0,5),(3,9)` decodes as the single run `(0,9)`; `(5,7),(0,2)` is reordered; a duplicate pair is
merged. All `Ok`, with the byte count still right. Read depth is raised over a witness, so a merged
run is a read credited with positions it never saw — and this is the one place in the decoder where
corruption produces a different valid record rather than an error.

**M6: [record.rs:530](../../../../src/ng/psp/record.rs#L530) — `take`'s overflow check has no regression test, and removing it panics**
**Categories:** reliability, idiomatic, extras. **Confidence:** High.
No fixture ever supplies a large *length prefix* — the hostile tests attack the two count fields.
With the `checked_add` removed, a length of 2⁶⁴−1 read at a non-zero offset wraps to an offset
behind the cursor and panics on a backwards slice index. The step's contract is that a corrupt psp
is a typed error and never a panic.

**M7: [record.rs:606](../../../../src/ng/psp/record.rs#L606) — a locus kind from a later minor version reads as corruption**
**Categories:** errors. **Confidence:** High.
Only the major version is enforced at open, and the unknown-trailing-field machinery exists so a
later minor *is* readable — but an unrecognised kind tag lands in `Malformed`, whose instruction is
*rebuild the file*. `header.rs` applies the opposite reasoning to the header, in its own doc.

**M8: [record.rs:183](../../../../src/ng/psp/record.rs#L183) — the doc promises a refusal no code performs, and the file it promises to refuse is accepted and misparsed**
**Categories:** extras, refactor_safety. **Confidence:** High.
The type's doc says a repeated field added later "cannot be skipped and this reader refuses the file
instead of guessing". Nothing refuses it, and nothing can: the manifest has no cardinality, so such
a field can only be declared once and is accepted. Built and measured —
`PER_OBS_FIELD ACCEPTED read=20 of 20`. With one observation the trailing skip happens to swallow
the extra byte; with two or more, everything after the first observation decodes from the wrong
offsets. **A maintainer reading this will believe the case is handled and skip the version bump
that is the only real protection.**

**M9: [record.rs:187](../../../../src/ng/psp/record.rs#L187) — `#[derive(Default)]` gives `RecordBodyLayout` a second, unlabelled constructor that makes a claim only a file may make**
**Categories:** defaults, refactor_safety, smells, idiomatic. **Confidence:** High.
`default()` is byte-for-byte `current()`, and both assert that a file's manifest declares these
nineteen fields with these encodings — including 4,096 steps to the natural log. Only
`from_manifest` has read a file and earned that. A probe confirmed the accidental route compiles
(`None.unwrap_or_default()`), and that a record decoded under a defaulted layout against a manifest
declaring 1,024 steps comes back unrescaled — the refusal bypassed by a value that looks like a
default. The derive is also unused.

**M10: [record.rs:133](../../../../src/ng/psp/record.rs#L133) — the declared quantisation step can be severed from `SummedLogError::STEPS_PER_NAT` and nothing notices**
**Categories:** defaults. **Confidence:** High.
Hard-coding `2_048` passes everything. The one guard kills only `1_024` — the literal the test
itself names as the wrong value. A writer declaring 2,048 puts every error sum in the file out by a
factor of two for any reader that believes the header.

**M11: [record.rs:441](../../../../src/ng/psp/record.rs#L441) — the encoder is exhaustive on `LocusKind` and the decoder cannot be, so a kind can be added write-only**
**Categories:** refactor_safety. **Confidence:** High.
Adding a variant *is* a compile error in `put_kind` — confirmed. But `kind()` matches a `u64` tag
and must end in a wildcard, so the obvious repair leaves the codec one-way and the suite green. The
three round-trip tests each name one kind, so a fourth adds no test by itself.

**M12: [record.rs:1044](../../../../src/ng/psp/record.rs#L1044) — the "walked past" test never uses more than one unknown trailing field**
**Categories:** reliability. **Confidence:** High.
With one element every ordering is the same ordering: reversing `unknown_trailing` survives. The
promise is about *two* fields — the window's GC fraction and its mean coverage — and the two-field
case is the only one that can tell an ordered walk from an unordered one. The path where a later
writer's trailing field is itself cut short is untested too.

**M13: [mod.rs:185](../../../../src/ng/psp/mod.rs#L185) — no `PspReadError` variant can carry either new error without losing its class**
**Categories:** errors. **Confidence:** High on the gap, Medium on the consequence.
`CorruptBlock`'s `#[source]` is a `std::io::Error` and its documented meaning is *the file is
damaged* — the wrong instruction for a short buffer, and the one thing D4's retry has to branch on.

### Minor

Twenty-two, of which the ones that were acted on: the truncation sweep runs only under a layout with
no unknown fields; `mapq_sum_sq` is the record's one 64-bit count and no fixture exceeds `u32::MAX`;
`entries_to_reserve` amplifies 12.4× (`size_of::<SequenceObservation>()` is 112 bytes against a
9-byte floor) with the floor itself unpinned, and a 1 MiB body reserves 13.0 MB in 4.3 ms; the
locus-kind tags are wire constants no test states; no fixture carries a byte string past 127 or a
base outside `ACGT`; `record_body_fields()` has never been through the header it exists to feed;
`a_rich_record()` carries six reference bases over a seven-base region, which its own sibling test
asserts is seven; two tests are the same test written twice (one mutation killed exactly those two
and nothing else); the decode is not injective, so byte-identity and record-identity are different
things; four of the nineteen wire names spell the Rust shorthand where the other fifteen spell the
quantity; one concept has four spellings (`Ssr`, `ssr-*`, "repeat motif", "STR"); the decode errors
name their fields in a third vocabulary, twenty-one hand-written strings already divergent from the
manifest's nineteen; `decode_body` returns a bare `usize` a caller can drop with `_`; `BodyBytes`
names bytes but is a cursor, and three things in the module now spell "body bytes"; nine
cursor-advancing methods are named as nouns; `room_for` is a preposition phrase taking two
interchangeable `usize`s positionally; `RecordLayoutError` drops the word its own type carries;
the module's summary line still says the file is one record's head.

### Nits

The test module re-imports seven names it already has; `from_manifest` allocates nineteen `String`s
to make nineteen comparisons that need none; `read_u32` and `read_u16` are the same six lines
twice; `encode_i64_svarint` is called directly between two `put_varint` calls, putting the sink on
opposite sides on adjacent lines; the unknown-field error does not read as a sentence; `bytes_left`
subtracts without saying why it cannot underflow; `unknown_field_count()` is read only by tests;
the two new error enums are the module's only `#[non_exhaustive]` types and carry no line saying
why; eight lines of design argument sit on a test doc.

## 7. Out of scope observations

- **`cargo clippy --lib --tests` is red on this branch** for three errors in A1–A3 test code (§3).
  It is why C1's test code had never been linted. **Fixed with the C1 fixes** rather than left, since
  the gate is wanted for C2 and C3.
- **[src/psp/varint.rs:93](../../../../src/psp/varint.rs#L93)** (frozen production tree)
  — `decode_u64_leb128` accepts a 10-byte encoding whose top byte carries bits above 64 and silently
  drops them, so an over-long-but-in-range encoding decodes to a truncated value rather than
  `Overflow`. It does not affect this diff's round trip. Production's code; not touched.
- **[header.rs:960](../../../../src/ng/psp/header.rs#L960)** — `ALL_ENCODINGS` is a hand-maintained
  sample of every `FieldEncoding` variant and a new variant does not flag it; only an exhaustive
  match in a test does. A1/A2's code.
- **The manifest carries no cardinality**, which spec §4.5 asks for. Recorded as a departure in
  A1+A2 §2.8; its consequence lands here as M8. A header change, so it belongs with C2 at the
  earliest, and it is the only thing that would let a repeated later field be refused rather than
  misparsed.
- **The decoder measures 12.46 M records/s** on the tomato-corner shape (19-byte body, one
  observation, hot in cache, no decompression) against `encode`'s 59.75 M/s, and against the
  20 M/s the specs quote for the measuring prototype five times over. There is no bench for this
  path. To Milestone D3, with a `benches/` entry so it has a baseline to move against.

## 9. What's good

- **The parse is sound against hostile input, and that was measured rather than argued** —
  600,492 decodes with overflow checks live, no panic, no overflow, and no `Ok` claiming more bytes
  than it was given.
- **Adding a `FieldEncoding` variant is a compile error in `skip`**, and adding a `LocusKind`
  variant is one in `put_kind` — both confirmed by actually adding one. The claims in the doc
  comments hold.
- **`a_field_this_reader_does_not_know_is_walked_past_when_it_comes_last` asserts the byte count**,
  not just the record, which is the strongest assertion in the file: it is what makes an
  under-consumed field detectable at all, and it killed two mutations on its own.
- **Production's varint codec is called and not reimplemented** — three one-line delegations, and
  no LEB128 or zig-zag arithmetic anywhere in `record.rs`.
- **The chain-id pin fails loudly the day Milestone E lands**, with a message naming the milestone,
  and its half-done form (encoder only) is caught harder still, by ten tests.
