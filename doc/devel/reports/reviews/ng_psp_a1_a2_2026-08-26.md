# ng psp store — A1 and A2 review

*Code review, 2026-08-26. Eight checklists, each run by its own agent in its own git worktree,
against commit `c4c163ee` on branch `ng-psp-encoding`. Per-category findings are the audit trail in
`tmp/review_2026-08-26_ng-psp-a1-a2/`.*

---

## 1. Scope

**What was reviewed:** the diff of `c4c163ee` against its parent `9ebbcdf4` — steps A1 and A2 of
[the psp store plan](../../ng/impl_plan/psp_file_format.md), run as one loop iteration.

**In-scope files:** [`src/ng/psp/mod.rs`](../../../../src/ng/psp/mod.rs),
[`header.rs`](../../../../src/ng/psp/header.rs), [`record.rs`](../../../../src/ng/psp/record.rs),
[`index.rs`](../../../../src/ng/psp/index.rs), [`footer.rs`](../../../../src/ng/psp/footer.rs), and
the one added line in [`src/ng/mod.rs`](../../../../src/ng/mod.rs).

**Out of scope:** the rest of the crate. `src/psp/` is production and frozen; it was read as an
ancestor pattern and **verified untouched** — `git diff 9ebbcdf4 c4c163ee -- src/psp/ src/ssr/
src/var_calling/ src/vcf/ src/pileup/` is empty, and both production items ng's tests read were
already `pub`, so the freeze's visibility exception was not used.

**Categories dispatched:** reliability, errors, extras, naming, module_structure, idiomatic, smells,
and one agent taking refactor_safety and defaults together. **`unsafe_concurrency` was skipped** —
the diff has no `unsafe`, no threading and no shared state — and **`tooling` was skipped**, because
`Cargo.toml` is unchanged. Both skips are recorded here rather than left silent.

## 2. Verdict

**Approve with changes.** One Blocker and fourteen Majors, all applied. The module's shape held up:
no finding asked for a different design, and the three that several agents found independently were
all defects in how a stated property was *enforced*, not in the property.

## 3. Execution status

Every agent ran the build in its own worktree. Verification on the reviewed tree, quoted from the
run: `cargo fmt --check` clean; `cargo clippy --lib --all-features -- -D warnings` clean;
`cargo test --lib ng::psp` → `26 passed; 0 failed`; `cargo test --lib --bins --tests --examples` →
`4558 passed; 0 failed; 14 ignored`. `--all-targets` was not run as a gate: it is red on `main` for
a pre-existing panic at `benches/psp_writer_perf.rs:386`.

**No finding is labelled "needs verification".** Every one below was demonstrated — by a mutation
that survived the suite, by a probe that produced the wrong output, or by a message quoted verbatim.

## 4. What the code got right, stated so the findings are read against it

- **The parser does not panic on anything.** Two agents fuzzed `Header::decode` independently:
  ~90,900 inputs (60,000 random buffers, 20,000 behind a real magic, every single-bit flip of a
  valid header, every truncation, TOML nested 100,000 deep) and 250,000 more (multi-bit flips,
  truncations, random buffers). **No panic, no arithmetic overflow, no unbounded allocation, no
  stack overflow**, in either run.
- **The dependency direction is clean.** Sweeping every `use crate::*` and inline `crate::` path:
  the module imports from `crate::ng::types`, `crate::fasta` and `crate::psp` (the last two in tests
  only) and **from no pipeline-stage module at all**.
- **The fourteen-row validation table is sound as far as it goes.** All 28 messages were dumped:
  every reader-half case reaches the `check_rules` rule it names, not a serde failure. Its defect
  was under-population, not a false pass.
- **`encode` is a function of the header's value alone** — 1,000 repeat encodes, an independently
  built equal value, and the parameter map rebuilt in four insertion orders all gave identical
  bytes.
- **Nothing hardcodes a value the file is supposed to carry.** There is no `Default` impl and every
  configuration type is a public-field struct literal, which is what spec §4.1's *the format fixes
  the grammar, the file carries the values* asks for.

## 5. Findings

### B1 — the offset `decode` returns was untested, and returning the wrong one passed everything

**Categories:** reliability. **Status: Applied.**

`decode` returns `(Header, usize)`, and the `usize` is where the first psp block begins. Every one
of the 26 tests handed it a buffer that was *exactly* the header, and the only assertion was
`header_bytes == bytes.len()` — on that fixture the correct answer and the buffer's length are the
same number. Replacing `Ok((header, header_bytes))` with `Ok((header, bytes.len()))` **survived all
26 tests**, reporting the first block at byte 5272 instead of 1176 on a header followed by 4,096
bytes of block data.

Milestone D seeks to that offset. A wrong value does not panic and does not fail to parse — it
starts the block reader at the wrong byte, which surfaces later as `CorruptBlock` on a file that is
not corrupt.

**Fix:** `decode_reports_the_header_length_and_not_the_buffer_length` asserts the offset against a
buffer where it differs from the length, and that the byte at that offset is the block's first.

### M1 — a same-major file that adds a key was refused as damaged

**Categories:** errors, smells, extras — **three agents, independently.** **Status: Applied.**

The wire types carried `deny_unknown_fields`, so a 1.1 header with one added key came back as
`MalformedHeader … "unknown field"` — *rebuild the file*, when the right instruction is *this reader
is older than the file and can still read it*. The test that appeared to pin the minor-version split
passed only because its 1.7 body added nothing.

The key one agent probed with is the **observation reach ceiling**, which
[spec §3.1](../../ng/spec/psp_file_format.md) already says the header will gain.

**Fix:** `deny_unknown_fields` removed, and `a_later_minor_that_added_a_key_still_reads` adds that
very key and asserts everything this reader knows still comes back.

### M2 — `encode` wrote a header its own reader refused

**Categories:** extras. **Status: Applied.**

`contig.length` and `genomic-block-size-bp` are `u64`. The `toml` crate **serialises** a value above
`i64::MAX` and its own parser then rejects one, and `check_rules` never looked at the magnitude.
Measured: `i64::MAX` round-trips, `i64::MAX + 1` is written and then refused.

**This falsified the property the commit message and the implementation report both led with** — *the
writer cannot produce a header its own reader would refuse*. The reachable half is the block size,
which is a writer's knob and so a typo away.

**Fix:** both magnitudes are rules in `check_rules`, against a named `MAX_TOML_INTEGER`, and the
table has a row for each. The boundary is pinned in both directions:
`the_widest_number_toml_can_carry_round_trips_and_one_more_is_refused`.

**Adaptation worth recording:** the two new rows' *reader* half cannot reach the rule — TOML refuses
the value at the syntax before any rule runs, which is precisely why the writer needs the rule. The
table says so rather than pretending otherwise.

### M3 — the writer's encoding names and the reader's were two lists, and only one was compiler-checked

**Categories:** refactor_safety, smells, idiomatic — **three agents.** **Status: Applied.**

Adding a seventh `FieldEncoding` variant made the compiler flag two sites; `encoding_of` was not one
of them, because its parameter check ended in `_ =>`. One agent added a variant, applied the two
minimal fixes the compiler asked for, and got `Header::encode` writing `encoding = "delta-varint"`
and `Header::decode` refusing those same bytes — **with the whole suite green**.

**Fix:** one list. `ALL_ENCODINGS` names every scheme, `FieldEncoding::spelled` is the single
exhaustive place a spelling is written, and `encoding_of` recognises exactly what that produces and
matches per-arm with no wildcard. Three tests hold it:
`every_scheme_the_writer_can_spell_is_one_the_reader_recognises`,
`the_encoding_list_holds_every_scheme_the_type_has` (an exhaustive match, so a seventh variant is a
compile error), and the unknown-encoding message now lists the schemes from that same list.

### M4 — `FOOTER_BYTES` did not pin the width its test claimed to pin

**Categories:** refactor_safety, smells. **Status: Applied.**

Adding a `u32` to `Footer` left `size_of::<Footer>()` at 48 — it fell in the struct's tail padding —
while the width on the wire became 52. The test asserted `size_of::<Footer>() <= FOOTER_BYTES`, so
both footer tests stayed green. Milestone F4 seeks that many bytes back from end-of-file.

**Fix:** the test adds up the fields' own wire widths rather than asking for `size_of`, and
`FOOTER_MAGIC` is now a named constant the sum includes.

### M5 — six of the validation rules were never exercised, and three fixtures were far from their boundary

**Categories:** reliability, smells. **Status: Applied.**

Four mutations deleting rules survived the suite and admitted files the format forbids: a contig
named `""`, a contig named `"SL4.0 ch00"`, `input-reference = "genomes/t.fa"`. And three fixtures
sat far past their rule's boundary, so a widened bound survived: the basename row used a
five-component absolute path (widening `> 1` to `> 2` admits every one-directory relative path); the
look-back window row used 40 (dropping the floor from 10 to 0 admits a window of 5); the digest row
failed on length alone (deleting the lowercase clause breaks encode/decode byte-identity).

**Fix:** the table is 24 rows, **every fixture one step over its boundary** — `MIN - 1` and
`MAX + 1` for the window, `genomes/tomato.fa` and `..` for the basename rules, a three-byte and an
uppercase and a too-long digest each in their own row.

### M6 — `check_basename` accepted `/` and `..`

**Categories:** errors, smells, extras. **Status: Applied.**

`Path::new("..").components().count()` is 1, so the rule the header documents as *only a basename is
recorded* did not fire on `..`, `.` or `/`.

**Fix:** the rule now requires one **ordinary** component, and `..` is a row in the table.

### M7 — every read error `decode` produced had an empty `source()` chain

**Categories:** errors. **Status: Applied.**

The `toml::de::Error` — with its span — and the `Utf8Error` were `format!`-ed into `reason` and
thrown away. Verified: every probe case printed `(no source() chain)`.

**Fix:** `MalformedHeader` carries an optional `source`, set wherever the fault was a parser's rather
than a rule's.

### M8 — "this is not an ng psp" was folded into "this ng psp is damaged"

**Categories:** errors. **Status: Applied.**

Those two carry different instructions — *you handed me the wrong file* against *rebuild this file* —
and the module's own doc calls the first the everyday case. A gzip, a BAM and a production `.psp`
produced byte-identical messages, and the module's own test had to string-match on
`contains("not an ng psp")` to recover the case.

**Fix:** `PspReadError::NotAnNgPsp { path, found, expected }`, whose message shows the bytes that
were actually there.

### M9 — `Io` named a mechanism and neither the file nor the operation

**Categories:** errors. **Status: Applied.**

`Io(#[from] std::io::Error)` on both enums rendered as a bare `No such file or directory (os error
2)`, while every other variant carries a path — from a cohort opening a thousand samples, that names
nothing. Cheapest to fix before any `?` site exists, and there are none yet.

**Fix:** `Io { path, while_doing, source }` on both enums, not `#[from]`. `PspWriteError::Reopen`
likewise became a named variant with a `#[source]`, so the chain says a *write* was in progress and
still reaches the read error — `#[error(transparent)]` said neither.

### M10 — `OutOfOrder` did not name the file

**Categories:** errors. **Status: Applied.** It is the one write error raised per record, and in a
cohort gathering sixty samples at once the file's name is the only thing that says which stopped.

### M11 — `RecordHead` states a shape Milestone E3 must break

**Categories:** refactor_safety. **Status: Applied, as documentation only.**

[Spec psp_record_encoding §6](../../ng/spec/psp_record_encoding.md) and plan step E3 put the
chain-id live-set changes **in the record head**. They are variable-length — 6.42 bytes a position at
293 reads — so they cannot live in a `Copy` struct or under a `size_of ≤ 32` assertion, and both the
derive and the assertion were argued on their own merits with no note of the collision.

The reviewer's recommendation, followed: **do not add the list to `RecordHead`** — A1 is right to
declare only the fixed part — but record the collision so E3 does not rediscover it. The module
diagram now shows `chain_id_changes` in the head, and both doc comments say the type is the fixed
part only.

### M12 — two spec defaults had no named constant

**Categories:** defaults. **Status: Applied.**

100 kb was prose in a doc comment and the look-back window's 15 existed only in a test fixture, so
Milestones D1 and D2 would have picked both at a call site where spec §4.1's reasoning is invisible.
`MAX_HEADER_BODY_BYTES` was a live reader limit no test pinned — cutting it sixteenfold left the
suite green — and the `10..=31` window bound and the message explaining it were independent literals,
so `12..=31` with the message still saying `2^10` passed.

**Fix:** `DEFAULT_GENOMIC_BLOCK_SIZE_BP`, `DEFAULT_LOOK_BACK_WINDOW_LOG`, `MIN_/MAX_LOOK_BACK_WINDOW_LOG`,
`FIXED_INTEGER_WIDTHS_BYTES`, `IEEE_FLOAT_WIDTHS_BYTES` — each used by both the check and the message
it prints, and each pinned by a test.

### M13 — no property or fuzz test for a parser over untrusted bytes

**Categories:** reliability, extras. **Status: Applied.**

Both agents' fuzzing found nothing, and **nothing in the suite protected either property**.

**Fix:** `decode_refuses_damaged_bytes_without_panicking` — 20,000 multi-bit-flipped and truncated
headers plus 400 random buffers, from a fixed seed so a failure is reproducible from the test name —
and `a_decoded_header_re_encodes_to_the_bytes_it_came_from`.

### M14 — the TOML keys read as two different things four lines apart

**Categories:** naming. **Status: Applied.**

`encoding = "fixed"` (a byte width) sat four lines from `encoding = "fixed-point"` (a rounding step),
and their parameters were `bytes` and `scale` while every message the module prints calls them a
*width* and a *step*. `window-log` dropped the *look-back* qualifier
[spec §2](../../ng/spec/psp_file_format.md) coined, inside the same `[manifest]` table as a field
named `window-mean-coverage`, which is a genomic span.

**Fix, and it changes the file format** — which is free now and expensive later, since no psp has been
written: `fixed-width-integer` / `width-bytes`, `ieee-float`, `steps-per-unit` (which says by itself
which way the arithmetic goes), and `look-back-window-log`. The Rust names follow:
`FieldEncoding::FixedWidthInteger`, `IeeeFloat`, and `Manifest::look_back_window_log`.

**Also renamed:** `ContigEntry` → `ContigIdentity`, which removes the shadowing of
`crate::fasta::ContigEntry` and pairs with `ReferenceIdentity` three declarations above. The two
differed only in `PartialEq` — the one property invisible at every use site.

### M15 — a test decoded the binary length prefix as UTF-8

**Categories:** naming (found while renaming). **Status: Applied.**

`a_parameter_is_written_as_its_bare_value` ran `String::from_utf8` over the *whole framed header*,
length prefix included. It passed only because the fixture's body was 1,147 bytes and `1147 & 0xFF`
is ASCII `{`. Renaming one wire key took the body to 1,157 and the test panicked with
`Utf8Error { valid_up_to: 4 }` instead of failing an assertion.

**Fix:** a `body_of` helper slices the body by its declared length, with the trap written down.

### Minors and nits — applied

The module's four submodules are `pub(crate)` with the surface re-exported, so every type has one
public path rather than two; the format constants a caller can act on are in that list, where only
`FOOTER_BYTES` had been; and `footer.rs`'s test no longer ties ng's width to production's
`pub(crate)` `TRAILER_BYTES` through arithmetic — the lineage is prose against a literal, so a change
to production's tail cannot fail an ng test.

## 6. Deferred — for Checkpoint A

Five findings are real and are **not** implementation-ready. Each needs a decision rather than a
patch.

1. **The 1 MiB header cap is a contig-count ceiling nobody wrote down.** Measured: with MD5s, 10,000
   contigs write and 12,000 are refused; without, 20,000 write and 50,000 are refused. The constant
   is copied verbatim from production and appears in none of the spec, the arch or the report.
   Fragmented draft assemblies exceed it, and ng's committed input range does not exclude them.
2. **`BlockIndexEntry` drops a field two live spec sections still require.** Spec §3.3 and §4.1 say
   the index carries the largest non-reference support in the block; §6.2 and the arch say it was
   removed. **The specs contradict each other**, and §4.1's live "1,000 kb may well be better"
   argument rests on the field existing.
3. **The manifest carries no cardinality** (arch §3.2 against spec §4.5) — already raised in the
   implementation report; the reviewers confirmed the cost is that a *list*-shaped unrecognised
   field cannot be skipped.
4. **The compression level has no home in the manifest**, though spec §1.2 names it as the user's and
   goal 4 says settings are recorded.
5. **`WriterProvenance.created` is a `toml::value::Datetime`**, putting a dependency's type in a
   public struct.

## 7. What this review cost, and what it bought

Eight agents, each in its own worktree, each building and mutating rather than reading: **19
mutations run with 11 survivors in the reliability pass alone**, four more in the refactor-safety
pass, and ~341,000 fuzz inputs across two agents. Every one of the three convergent findings — the
unknown-field refusal, the split encoding tables, the untested footer width — was found by an agent
that changed the code and watched what did not fail. **None of them was reachable by reading**, and
all three passed a green suite.
