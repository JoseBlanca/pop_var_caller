## 2. Verdict

**Request-changes. No Blocker, four Majors — and three of them are the same test.**

**The test named for the block boundary could not see a block boundary.**
`a_read_that_comes_back_across_a_block_boundary_arrives_again` had a fixture whose live set was
**empty at the cut** — the test asserted so itself — and read the second block with a *fresh*
reader, which has no state to carry. So neither half of what its docstring claimed was exercised:
not the read still covering across the boundary being restated, and not a reader failing to reset.
**All three agents reached it independently.** Measured: of 22 mutations, this test caught exactly
one, and fourteen other tests caught that one too; making the writer's `start_block` a no-op, the
reader's `start_block` a no-op, and injecting the step's own headline defect all left it green.

**The property test's docstring promised a guard it did not have.** It said *"a shrink that removed
the re-entry would fail rather than pass quietly"*, but its arrival count is computed from the same
records on both sides — self-consistent, and satisfied exactly by a draw containing no re-entry at
all. Demonstrated on a fixture where every read covers one stretch.

**And the fixture generator could not tell two of its four arguments apart.** Transposing the mate
length with the gap between the mates gives **the same 800 identifiers, the same 660 covering two
stretches and the same 1,460 stretches**, because a mate starts at the sum of the two either way —
so the comment saying "30-base mates, a 40-base hole" was a claim nothing checked.

**The step's central oracle holds, and holds the thing it is for.** Closing the hole between the
mates — the fixture losing its re-entry — is caught by `most_reads_go_live_twice…` **and by no
other test in the suite**. The re-entry code paths E1's review found dead are now genuinely
reached: instrumentation counted `apply_arrivals`' interleaving arm entered **1,320 times** by that
one oracle.

## 5. Findings

### Major

**S1: [chain_ids.rs:1173](../../../../src/ng/psp/chain_ids.rs) — the block-boundary test contains neither behaviour its docstring names**
**Categories:** smells, extras, reliability — **all three agents.** **Confidence:** High.
Measurements in §2. Its docstring, report §3's table and the commit message all assert the half the
fixture omits.

**R1: [chain_ids.rs:1512](../../../../src/ng/psp/chain_ids.rs) — the sortedness property asserts an invariant where it cannot be violated**
**Categories:** reliability. The live set can only stop being sorted when an arrival sorts *below*
an id already live — the re-entry shape the whole step is about — and uniform random bytes
essentially never build a set for one to sort under. Two measurements: the interleaving arm entered
**0 times over 600 cases**, and a mutation making `apply_arrivals` append instead of merge left the
test green while four others caught it.

**S2: [chain_ids.rs:1469](../../../../src/ng/psp/chain_ids.rs) — "a shrink that removed the re-entry would fail" is not what the assertion says**
**Categories:** smells, reliability — **two agents.**

**RS1: [chain_ids.rs:133](../../../../src/ng/psp/chain_ids.rs) — `LiveSetChanges::departed()` has no test that can fail**
**Categories:** reliability. Replacing its body with `&[]` leaves all 228 `ng::psp` tests green —
the only test reading it asserts the list is *empty*, which `&[]` satisfies. E4's residual
arithmetic is specified against these counts.

### Minor and Nits

Nineteen between the three. Acted on: the fixture generator's four positional `u64`s, two of which
transpose invisibly; the "more than four fifths" threshold spelled `× 10 > × 8` with the number
nowhere in the assertion; the three headline figures (800, 660, 1,460) stated in a comment and
asserted nowhere, so drift would pass; the departure-count bound relaxable by one with all 228
tests green; the justification for "more than twice" arguing the wrong way — under an allocator
that never reuses an id, a read named twice gives two identifiers of one stretch each; a fourth,
fifth and sixth hand-rolled write-and-read loop, three of them added by this diff; `alone` as a
name for a reader, where the same word already names a `Vec` of live sets; `all_of_them` and
`all_the_stretches` as pronouns for counts the message supplies nouns for; the property test's
record count taken from `masks[0].len()` alone, truncating every other mask; and `pair_span - 1`
underflowing if the helper is reused with zero-length mates.

  8 MiB allocation were all reported.

  stretches, 140 one-stretch identifiers, identifier 9 going live exactly five times, and the three
  test counts.
- **The diff matches its stated intent.** Every hunk in `chain_ids.rs` lands at line 635 or later
  and `#[cfg(test)]` is at 634, so "adds no bytes and no production behaviour" is exact.
- **`errors` and `defaults` are honestly No findings**, checked over the whole file rather than the
  diff: the one `expect` carries its `// PANIC-FREE:` invariant, every wire-derived addition is
