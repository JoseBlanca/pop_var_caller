## 4. Open questions and assumptions

1. **A record can span past the next block's first position, and nothing in the index says so.**
   Production's entry carries a `last_pos` that its overlap predicate needs; ng's dropped it
   deliberately (spec §3.3). Whether `records_from` must therefore start a block *earlier* than
   the one whose first position brackets the coordinate is **G1's question**, raised here
   because F1 is where the missing field would have lived. Not a defect in F1.

## 5. Top 3 priorities

1. **B1** — the ordering scan was only ever exercised on its first pair.
2. **B2** — an error message that panics while being printed.
3. **M1** — the entry-width constant is wrong, and nothing could have told us.

## 6. Findings

### Blocker

**B1: [index.rs:126](../../../../src/ng/psp/index.rs) — every ordering fixture is two entries
long, so the scan runs one iteration in every test that can fail**
**Categories:** reliability, idiomatic/defaults (cross-category), refactor_safety.

`.take(1)` on `entries.windows(2)` left all 13 tests green while the decoder accepted indices it
should refuse — positions 100/200/**150** came back `Ok(3 entries)`, and an eleven-entry index
whose last position drops to 1 came back `Ok(11)`. **On a 154-entry index that is 152 of 153
pairs unchecked.** This is precisely the silently-wrong-block path the ordering rule exists to
close.

**B2: [index.rs:221,234](../../../../src/ng/psp/index.rs) — `Display` panics at entry 0**
**Categories:** errors, reliability, idiomatic — three agents, and reproduced by the author.

Both ordering variants computed the earlier entry's number as `entry - 1` *inside the message
template*. Rendering one whose entry is 0 panics with `attempt to subtract with overflow`;
in release it prints entry 18446744073709551615. `decode_index` never produces entry 0 there,
but the variants are public, constructible, and built by hand in this file's own tests — and
this fires in the **logging** path. **The one type whose stated contract is that a damaged file
is never a panic, panicking while reporting a damaged file.**

### Major

**M1: [index.rs:48](../../../../src/ng/psp/index.rs) — `LARGEST_ENTRY_BYTES` is 18; the widest
entry is 23**
**Categories:** naming, extras, idiomatic, refactor_safety — four agents.
A contig is a `u32` (five varint bytes) but a position is a `u64` (**ten**). The number was
carried over from production, where all four index fields genuinely are `u32`; ng widened one
and the arithmetic did not follow. `the_widest_value_of_every_field_round_trips` already builds
the very entry the doc said could not exist. Nothing was corrupt — a `Vec` grows — but a
constant named for a bound must hold it, and **no test could have caught it**, because nothing
observable reads a reservation.

**M2: [index.rs:128](../../../../src/ng/psp/index.rs) — no fixture has a position that resets at
a contig boundary, which is what every real psp looks like**
**Categories:** reliability.
The 154-entry fixture uses `1 + block * 100_000`, so raw position rises across contig boundaries
too. A decoder comparing raw positions and ignoring contigs passes all 13 tests while refusing
the legal index `(0,1) (0,90000000) (1,1) (1,500)`. The opposite direction *is* caught, so the
fixture was half discriminating.

**M3: [index.rs:154](../../../../src/ng/psp/index.rs) — nothing pins `checksum_index` to
production's XXH3**
**Categories:** reliability.
Swapping the body for FNV-1a survives all 13 tests; the values differ (683,841,834 against
1,094,245,170). The test asserted **avalanche**, which any hash satisfies — so every psp this
build wrote would carry a checksum no other build agreed with, and nothing would fail first.

**M4: [index.rs:168](../../../../src/ng/psp/index.rs) — an over-long varint is reported as a
truncation, and the sentence it prints is false**
**Categories:** errors, extras.
`decode_u64_leb128` distinguishes *truncated* from *overflow*; both arrived as `Truncated`,
whose message says "the index ends inside entry 0". Measured on a 19-byte buffer with **nine
bytes still unread**. No test fed an over-long varint at all.

**M5: [index.rs:196-241](../../../../src/ng/psp/index.rs) — nothing pins any rendered message**
**Categories:** errors.
Cutting `Truncated`'s message to "the index is damaged" passes 13 of 13; mislabelling the
position field as the contig passes 13 of 13. Only `"contig"` was ever asserted;
`"first-position"` and `"offset"` appeared in no test. `mod.rs` pins `PspReadError`'s text for
exactly this reason.

**M6: [index.rs:64](../../../../src/ng/psp/index.rs) — a field added to `BlockIndexEntry` is
silently dropped by the encoder**
**Categories:** refactor_safety.
`encode_index` reads fields one at a time, so adding `record_count` gives compile errors in the
decoder and the test helpers but **none in the encoder**. Repairing them the way the compiler
invites leaves 13/13 green with the new field never written. Catching it depended on a fixture
literal.

### Minor

`offset` on the entry means *bytes* while unqualified *offset* elsewhere in this module means a
base-pair distance, and production spells this one `block_offset` (naming); `entry` names both a
struct and an ordinal, and `at` is a preposition doing duty as a byte cursor (naming); the
`field: &'static str` is a stringly-typed closed set, and `FieldTooLarge` admits fields that
cannot raise it (naming, smells, idiomatic); the offset's width is stated three times, one of
them an `expect`, and changing only the first compiles and turns eight tests into panics
(refactor_safety); `{offered:?}` prints a `GenomePosition` struct dump into a user-facing
message (errors); the checksum doc's claim that the index is the one region no frame checksum
covers is **false of ng's layout** (naming); the decode's doc announces the check that moved in
but not the two that stayed out — contig numbers are never checked against the header's contig
list and offsets never against the file's length (defaults); padded LEB128 is accepted, so an
index has more than one byte form and its checksum moves with it (extras); `decode_index` is 54
lines mixing three jobs (smells); `windows(2)` then `pair[0]`/`pair[1]` (refactor_safety).

### Nits

The F1 plan entry is ticked while its own words — "built while writing and decoded whole at
open" — describe F3 and F4; a `first-position` of 0 is accepted though `Position` is documented
1-based; the single golden pins 11 bytes but not a wide offset.
