# Code Review: ng psp D2 — the capped look-back window, and the head-encoding measurement
**Date:** 2026-08-27
**Reviewer:** rust-code-review skill (orchestrator), eight category checklists across five sub-agents, each in its own git worktree
**Scope:** commit `2200001f` on `ng-psp-encoding` — `BlockCompressor`, the on-disk block framing, and `examples/ng_psp_head_encoding.rs`
**Status:** Request-changes

## 2. Verdict

**Request-changes. One Blocker, eight Majors, five wrong numbers — and every one of the largest
findings is the same shape.**

**The compressor has four settings, each had exactly one test, and none of those tests used the
configuration a writer ships with.** The window cap was proved only at a 1 kB window and level 1;
every test on the shipped path compressed a payload *under* the 32 kB window, where zstd narrows
the frame's own declaration to fit and the cap is inert. Guarding the cap with
`if level < ZSTD_COMPRESSION_LEVEL` compiles, raises no clippy warning, passes all 42 tests — and
makes every file need a wider window than its own manifest declares, which is the file D3's
decoder refuses block by block.

**The measurement, though, is sound and stronger than the commit claimed.** Every published
figure reproduced exactly on an independent rebuild, and twelve further fixed widths were tried
without finding one that beats variable-length on either sample.

**And five numbers were wrong**, four of them the author's own claims about the author's own
fixtures — the failure this project has now recorded in four consecutive milestones.

## 4. Top 3 priorities

1. **B1 — the window cap is untested at the shipped settings**, and half the test that looks like
   its guard cannot fail at all.
2. **M1 — the compression level reaches zstd untested** (four agents, independently): clamping
   every block to level 3 passes everything.
3. **M2 — a block's declared length is believed without being checked** (four agents): under
   fuzzing it reported a length longer than the bytes it was given 656,785 times, and the module's
   own walk slices on it.

## 5. Findings

### Blocker

**B1: [block.rs:786](../../../../src/ng/psp/block.rs) — the window cap is never tested at the settings a writer ships with, and the half of the test that would catch it cannot fail**
**Categories:** refactor_safety (Blocker), reliability (Major) — **two, from different angles.**
**Confidence:** High.
Both tests proving the cap reaches zstd call `at_level(w, 1)` at `w = MIN_LOOK_BACK_WINDOW_LOG`.
Every shipped-path test compresses about a kilobyte, under the 32 kB window, so zstd narrows the
frame's declaration and the cap is inert. Measured: `if level < ZSTD_COMPRESSION_LEVEL` around
the `WindowLog` call gives `42 passed; 0 failed`, no warning. Separately, at the minimum window
"one exponent less" asks for a window below zstd's floor, so the *parameter* is refused and the
frame is never examined — proved by substituting `b"not a frame at all"` for the frame: still
green.

### Major

**M1: [block.rs:775](../../../../src/ng/psp/block.rs) — the compression level reaches zstd untested**
**Categories:** reliability, errors, defaults, refactor_safety, smells — **four agents.**
`Compressor::new(level.min(3))` passes 42/42; so does appending
`set_compression_level(ZSTD_COMPRESSION_LEVEL)`, which forces every caller to 9. The only
level-mentioning test compares `new(w)` against `at_level(w, 9)` — the same level on both sides —
and otherwise asserts a literal against a literal. Measured behaviour: the same 4,000-record block
is 1,394 bytes at level 9 and 1,542 at level 3.

**M2: [block.rs:855](../../../../src/ng/psp/block.rs) — `compressed_block_bytes` returns a length taken from untrusted bytes with nothing bounding it**
**Categories:** reliability, errors, idiomatic, extras — **four agents.**
A block truncated to 36 of 73 bytes still returns `Some(73)`; five bytes whose prefix reads
`u32::MAX` return `Some(4294967299)`. Fuzzing over 700,000 inputs: a length longer than the slice
656,785 times. It is `pub`, newly re-exported, and the module's own walk does
`&file[at + 4..at + whole]`. It also erases the `Truncated`/`Malformed` distinction this module
types everywhere else, at the first seam a D3 reader meets.

**M3: [block.rs:771](../../../../src/ng/psp/block.rs) — `BlockCompressor` never sees a `Manifest`, so a manifest field it must honour has no compiler-flagged home**
**Categories:** refactor_safety, errors, defaults.
`BlockCompressor::new` takes a bare `u8`. Adding a field to `Manifest` that a compressor would
have to honour flagged three sites and **none of them was the compressor** — and the one a coder
would reach, `BlockBuilder::from_manifest`, has a comment sending them away. Measured
consequence: `BlockCompressor::new(20)` compresses happily and a decoder configured from a
manifest declaring 15 refuses the frame with `zstd code 18446744073709551600`, which is exactly
the unactionable error spec §4.2 says the declaration exists to prevent.

**M4: [block.rs:830](../../../../src/ng/psp/block.rs) — nothing compresses a payload zstd cannot shrink**
**Categories:** smells, refactor_safety, extras — **three.**
`reserve(payload.len())` instead of `reserve(compress_bound(payload.len()))` passes 42/42, and
fails on a block holding one record — which compresses to a frame *longer* than its payload, and
which is ordinary at sparse coverage. Every compression fixture builds forty records or more, so
the branch the bound exists for is never reached. **The oversizing is what hid it**: cutting three
of those fixtures to one record each is what kills the mutation.

**M5: [block.rs:845](../../../../src/ng/psp/block.rs) — the on-disk framing has no golden anchor**
**Categories:** extras.
Writing *and* reading the length big-endian was killed by exactly one test, and by that test's
incidental byte literals rather than its subject. Rewritten as a round trip, the same coordinated
change goes green — 158 passed, 0 failed. The framing is the format: nothing in a file declares it.

**M6: [block.rs:778](../../../../src/ng/psp/block.rs) — `with_level` checks the argument it shares with `new` and not the one it exists for**
**Categories:** defaults.
Probed: `at_level(15, 23 | 100 | i32::MAX)` all return `Ok` and all produce exactly the level-22
output; `at_level(15, 0)` is not level 0 but zstd's default 3; `at_level(15, -131_073)` is accepted
and gives a block 169× the shipped level's. zstd clamps silently, so a caller measuring the
level's cost reads the same number twice and concludes the level stopped mattering.

**M7: [block.rs:706](../../../../src/ng/psp/block.rs) — the level is unrecoverable everywhere**
**Categories:** defaults.
Not in the file, not from the writer's version (`at_level` is public, so it varies within one
build), and not from a running compressor, which never stores it. Goal 5's byte-identity check,
append (§6.4) and every byte figure the specs quote all need it. The header already has the home:
`WriterProvenance.parameters`, "one entry per exposed knob".

**M8: [ng_psp_head_encoding.rs:102](../../../../examples/ng_psp_head_encoding.rs) — the fixed-width arm of the measurement has no oracle**
**Categories:** reliability.
`check_against_the_shipped_cut` runs for the varint arm only. The `Fixed` branch — its widths, its
bound, its field order — is checked by nothing at run time and by no test, and it is the arm
producing the numbers that close arch §7.

### Minor and Nits

Thirty-one between the five agents. Acted on: `BlockCompressError::Zstd`'s message and source are
untested, and stripping `#[source]` passes 42/42; the manual `Debug` does not destructure `Self`,
so a setting added to the compressor silently stops being reportable, and its doc claims "the two
settings" while showing one; the compressor's fields are `inner`/`frame`/`block`, and `self.block`
sits three lines from a parameter named `payload` that *is* a psp block — spec §2's vocabulary
hazard for the fourth review running; `at_level` is a prepositional phrase where Rust's alternate
constructor idiom is `with_`; `COMPRESSED_BLOCK_LENGTH_BYTES` (4) and `compressed_block_bytes()`
(4 plus the frame) differ by one character and mean different things; in the harness the same four
identifiers name the head's *values* in one function and their *byte widths* in the type beside
it; and three fixtures build forty records where one would do.

## 6. Out of scope observations

- **A frame's own declared window is routinely *narrower* than the file's** — zstd shrinks it to
  fit a small payload, so an ordinary block under a 32 kB declaration writes a frame needing 1 kB.
  Spec §4.2 calls a mismatch "a corruption worth detecting"; **the check has to be `≤`, not `=`**,
  or D3 rejects nearly every block of every file this writer produces. A trap set directly under
  the next step.
- **`block.rs` at 2,247 lines was judged not to need splitting yet** — module_structure did not
  object, and arch §1 assigns all three concerns to this file by design. What the deferral owed
  was a module doc that stopped saying "nothing here compresses".
- **`psp` imports `SampleLocusObservations` from `locus_generation`**, a pipeline stage, while
  calling itself a peer. Pre-existing and public API; Milestone F is the last cheap moment.
- **`MAX_LOOK_BACK_WINDOW_LOG = 31` is zstd's 64-bit-only bound** with nothing linking it to that
  fact.

## 7. What's good

- **The measurement holds, and holds harder than claimed.** An independent rebuild reproduced all
  eight bytes-a-record figures, all four percentages, both record counts, both block counts and
  the refused field exactly. Twelve further fixed widths, four grids and six windows found nothing
  that beats variable-length: varint's head is already 4.000 bytes a record on tomato, the
  one-byte-per-field floor.
- **The harness's self-check is load-bearing and it works.** Weakened from byte-for-byte to a
  length comparison, the same injected field swap runs to completion and reports plausible
  different numbers (16.256 / +3.74 %). Three separate harness defects abort the run as written.
- **`compressed_block_bytes` never panicked** across 700,000 fuzzed inputs, and never disagreed
  with an independent model of what it should return.
- **The two-buffer design's justification was checked against the dependency's source**
  (`zstd-safe-7.2.4/src/lib.rs:1687`) and is exactly right.
- **`ContentSizeFlag(false)`, the frame checksum and the one-compressor-per-writer shape each have
  a test that kills their mutation**, and the content-size one was written *because* the first
  round of falsification found it surviving.
