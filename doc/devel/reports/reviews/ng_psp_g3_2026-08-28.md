## 4. Findings

### Blocker

**B1 — a damaged footer makes `replace_trailer` overwrite the header, the blocks and the index,
and return `Ok(())`.**

`decode_footer` proves the index ends exactly where the trailer begins, and the only lower bound
on either was the four-byte head magic. So a footer claiming `index_offset = 4`,
`index_bytes = 0`, `trailer_offset = 4` passes every check the footer can make about itself, the
sections rule and the index-inside-the-header rule — and the rewrite seeks to byte 4 and writes
there.

Reproduced in the main checkout, verbatim:

```
PROBE open says: Err(Damaged { reason: "the block index checksums to 0x38d394c2; …" })
PROBE replace says: Ok(())
PROBE size 3742 -> 56
```

**A 3,742-byte psp that `PspReader::open` already refuses became 56 bytes, reported as success.**

**B2 — "a crash in the middle leaves a file every reader refuses" is false, and the file it
leaves is one a reader accepts with a trailer that is neither the old one nor the new one.**

The rewrite overwrote in place and trimmed afterwards, so until a write passed the old trailer's
end the old footer was still there and still consistent. Reproduced in the main checkout by
writing the new payload and stopping:

```
crash after a 20-byte trailer: OPENED, trailer = "a per-sample summar!"
crash after a 20-byte trailer: OPENED, trailer = "a per-sample summarY"
crash after a  5-byte trailer: OPENED, trailer = "short-sample summary"
crash after a 32-byte trailer: refused: the footer does not decode
```

**`"short-sample summary"` is the new payload spliced onto the tail of the old.** One agent
enumerated every stopping point on the standard fixture and found **20 of the 21 torn states
accepted**. It is reachable without a crash: a short `write_all` on a full device returns `Err`
and leaves exactly that file.

### Major

**M1 — `a_footer_that_does_not_describe_the_file_is_refused` nudges the length one way only.**
Weakening the rule from `!=` to `>` — which accepts every file whose sections stop short — left
all 370 tests green. **This is the F4 Blocker exactly**, in the rule this operation copied from
`open`, one commit after it was fixed there.

**M2 — `a_file_that_is_not_a_psp_is_refused_and_left_alone` never reaches what it names.** Its
fixture is 47 bytes, one short of a footer, so the call returns at the length check and the magic
is never examined; and `matches!(refused, Reopen { .. })` cannot tell `Incomplete` from `Io`.

**M3 — nothing holds the causes the second half of the step exists to attach.** Replacing
`Some(source.into())` with `None` left 370 green. And `ManifestRefusal::Compressor` has **no
reachable construction site**: `header.rs`'s own validation refuses those manifests first as
`InvalidHeaderField`.

**M4 — `read_the_footer` is `PspReader::read_footer` copied, and the stated reason for copying it
is not true of the thing copied.** The argument was that `open` reads the index and header in the
same breath — `read_footer` does neither.

**M5 — a failure before the first byte and a failure after it return the same error shape**, so a
caller cannot tell *nothing happened* from *the file is now torn*, and the two need opposite
actions.

### Minor

- **The step's own claim "no `Display` repeats its own cause" fails for the one chain it
  created**: `UnsupportedManifest` renders links [1] and [2] as the same sentence, because
  `BlockCutRuleError::UnsupportedRecordLayout` interpolates `{source}` into its own message.
- **The trim comment's mechanism is wrong**: removing the `set_len` does not make the file
  refused, it makes the reader return a wrong trailer.
- **`retrailer.rs` is a coined word.** `trailer.rs` beside `reader.rs`, `walk.rs` and `writer.rs`.
- **Arch §1's module tree does not list the new file** — the third step running.

## 5. The author's own numbers

Two were wrong, both about this work:

- **"the nine construction sites" is ten.** Re-counted: two `UnsupportedManifest`, one
  `RecordRefused`, two `BlockRefused`, five `WouldNotBeReadable`.
- **The defect table's first row describes a mutation that was not run.** The label was *the file
  is never trimmed*, caught by 4; the mutation actually run set the length to `u64::MAX`. Deleting
  the `set_len` — the mutation the label describes — is caught by 1. Two true statements about two
  different mutants, and the table claimed one while running the other.

370 against 361, 4,907 against 4,898, and nine tests added: all correct.

## 6. What's good

- **Not reading the block index is right**, both agents agreed: it would cost a decode per call
  and every field written back except the trailer's length is the file's own.
- **The byte-identical comparison** in `replacing_a_trailer_leaves_the_blocks_and_the_index_byte_identical`
  is the right strength — an index that happened to decode the same way would pass a weaker check.
- **`WouldNotBeReadable` keeping its `reason`** was checked by compiling the alternative: two tests
  fail without it, because the causes do not name their own structure.
- **`InvalidHeaderField`'s exemption is defensible**, both agents agreed.
- **11,001 hostile mutants, no panic, and every refusal byte-identical.**
