# Code Review: ng psp C3 — the body stands on its own
**Date:** 2026-08-26
**Reviewer:** rust-code-review skill (orchestrator), five sub-agents covering eight checklists, each in its own git worktree
**Scope:** commit `408f691d` on `ng-psp-encoding` — the oracle for "a skipped body strands nothing"
**Status:** Request-changes

---

## 1. Scope

- **What was reviewed:** the diff of one commit — step C3 of
  [psp_file_format.md](../../ng/impl_plan/psp_file_format.md).
- **Reviewed against:** `408f691d0a0c7a4de46b79a3da47d2f167406589`.
- **In-scope:** [src/ng/psp/record.rs](../../../../src/ng/psp/record.rs) — two doc comments and the
  test block under the `C3 —` banner; and the commit's own reports.
- **Out of scope:** the frozen production tree `src/psp/`; `examples/ng_generic_loci_dump.rs`
  (11 pre-existing failures).
- **Categories:** all eight, across five agents. `reliability`, `extras` and `refactor_safety` ran
  alone; `smells` and `naming` shared an agent, as did `errors`, `defaults` and `idiomatic`.
  **The pairing is because C3 adds no error variant, no configuration value and no production
  function** — three checklists have a small surface on a test-only commit. Each was told that a
  small surface is not no surface, and each found something.

**⚠ The tests are the deliverable here, so reviewing them is the review.** Every agent was told
not to treat "few production lines changed" as "little to review", and to ask whether the property
claimed is the property proved.

**What the five did.** **63 mutations** applied and run (**28 survived**, 1 shown to change no
behaviour), and every one of them reproduced the author's own falsification independently.

## 2. Verdict

**Request-changes. Two Blockers, and both are the same shape: the oracle could not fail.**

- The harness never checked that it built what it was told to build, so a `walk_keeping` that
  returned nothing left every C3 test green.
- The fixture carries no chain ids, so **a correct Milestone E and an incorrect one are
  indistinguishable to it** — measured, both give the same three failures and leave all five C3
  tests passing. That is exactly the future defect the step exists to guard against.

**The author's own falsification reproduces exactly** — three agents got `64 passed; 6 failed`
independently, with the six the report names. So the oracle does catch the *one* defect it was
tested against. It is the defects next to that one it could not see.

**And three of the diff's own claims were measured wrong**, one of them the same class the C2
review caught.

## 4. Top 3 priorities

1. **B1 — the harness never checks what it built.** A one-line change to it passes the whole suite
   and disables three of C3's five tests.
2. **B2 — the fixture has no chain ids**, so the oracle cannot tell a right Milestone E from a
   wrong one, which is the thing the commit says it protects.
3. **M1 — the fixture's whole variety is unguarded.** Collapsing twelve varied records to twelve
   identical one-base ones leaves all 70 tests green, and the encoded run drops from 16,477 bytes
   to 396.

## 5. Findings

### Blocker

**B1: [record.rs:3655](../../../../src/ng/psp/record.rs#L3655) — `walk_keeping` never checks that it built the records it was asked to build**
**Categories:** reliability, refactor_safety — **two, independently.** **Confidence:** High.
Replacing `built.push(Some(decoded.record))` with `built.push(None)`, leaving the advance
untouched, gives `70 passed; 0 failed`. A harness that builds nothing at all
(`if keep(index) && bytes.is_empty()`) does too — probe confirms the kept counts go
`12/6/6/3/1/0 → 0/0/0/0/0/0`, so the oracle's inner assertion never runs once. Stacking the
author's own defect on top drops the failures from six to three, and **the three that go green are
C3's own** — the named oracle, its strongest form, and the mask test. C2's miniature version already
guarded this (`assert_eq!(kept, 2, …)`); the twelve-record rewrite dropped the idiom.

**B2: [record.rs:3626](../../../../src/ng/psp/record.rs#L3626) — the fixture carries no chain ids, so a correct Milestone E and an incorrect one are indistinguishable**
**Categories:** refactor_safety, reliability. **Confidence:** High.
The doc comment says the exception lists "will be measured from zero rather than from the previous
record" and the report says this test "is the one that will fail if E puts the wrong half in the
wrong place". Measured, by building both: E's exception list done **correctly** fails three tests,
all format goldens; done **incorrectly** — each id a step from the last id written, across records —
fails **exactly the same three**, with all five C3 tests green. Putting the live-set changes in the
body instead of the head gives four failures, **none of them a C3 test**. Give the fixture ids and
the wrong codec fails four of the five. **The oracle is sound; the fixture never reaches it.**

### Major

**M1: [record.rs:3570](../../../../src/ng/psp/record.rs#L3570) — every property the fixture's doc claims is asserted by nothing**
**Categories:** smells, defaults, refactor_safety — **three.** Measured: twelve varied records
collapse to twelve identical one-base generic ones with gap == span, and the suite stays at
`70 passed` while the run drops from 16,477 bytes to 396. Individually: `at += span` (so every gap
*is* its span) survives; the span list flattened to twelve `1`s survives; `rem_euclid(3)` widened so
only one kind occurs survives; `0..300` cut to `0..3` survives. **Two of the doc's claims are also
false as written** — "the gaps are never the spans" is the same finding C2 filed against the fixture
this one replaces, and "one at the top of the depth range whose head fields need more than a byte
each" is three records, of whose four head fields two need one byte.

**M2: [record.rs:3853](../../../../src/ng/psp/record.rs#L3853) — the property test covers about 250 of the 4,096 masks, and three documents say "every"**
**Categories:** reliability, naming, extras, idiomatic — **four.** `mask in 0u16..4_096` is a
strategy, not an enumeration; proptest's default is 256 cases and nothing overrides it. Three agents
instrumented it independently and got 246, 249 and 250 distinct masks. An exhaustive loop is
*cheaper* than the property machinery at this size.

**M3: [record.rs:3634](../../../../src/ng/psp/record.rs#L3634) — every tract record carries the same motif and flanks, so a payload taken from another record is invisible**
**Categories:** reliability. An `SsrDetail` returned from the *previous* Ssr record passes all 70
tests — C3's exact defect class. Proof it is not a no-op: change one record's motif and the same
mutant fails three C3 tests. Nothing else in the module covers it either, because
`any_record_round_trips_exactly` pins `LocusKind::Generic`.

**M4: [record.rs:3814](../../../../src/ng/psp/record.rs#L3814) — `the_head_carries_state_across_records_and_the_body_carries_none` asserts only the first half of its name**
**Categories:** smells, idiomatic. Its first half is byte-identical to the `"none at all"` pattern of
the test above it; its second half is a weaker restatement of C2's
`a_base_stale_by_one_record_moves_every_record_after_it`, which asserts *how far* the record lands
early where this one asserts only that it differs. It is the one C3 test that survives the author's
own injected defect.

**M5: [record.rs:3631](../../../../src/ng/psp/record.rs#L3631) — every record's reference bases are a run of the same byte**
**Categories:** reliability. A decoder returning the *previous* record's `reference_bases` whenever
the lengths agree passes all five C3 tests; only a C1 property test catches it, and only because it
generates arbitrary bytes.

**M6: [record.rs:3580](../../../../src/ng/psp/record.rs#L3580) — `a_block_of_records` takes a term the spec reserves, for a thing that is not one**
**Categories:** naming. Spec §2 defines a psp block as records over one span of reference compressed
as one unit, and blocks arrive at D1 — which C3 is the dependency of. The fixture is 232 bases of
records in memory against a 100,000 bp default block. **This is the third review running to unpick a
term reused for something it already means** (C1's `body`, C2's `body-bytes`).

**M7: [record.rs:3584](../../../../src/ng/psp/record.rs#L3584) — the record count is a literal in three places and pinned in none**
**Categories:** defaults. Dropping one span leaves `71 passed` while `("only the last", |index|
index == 11)` silently becomes a second copy of `"none at all"` — the pattern that asserts nothing.

**M8: [record.rs:3859](../../../../src/ng/psp/record.rs#L3859) — `1 << index` on a `u16` caps the fixture at sixteen records**
**Categories:** idiomatic. A seventeenth record panics `attempt to shift left with overflow` from
inside the proptest, saying nothing about the fixture that caused it; in release it would wrap and
silently cover fewer patterns than it reports. The fixture is expected to grow at Milestone E.

**M9: [record.rs:577](../../../../src/ng/psp/record.rs#L577) — "the signature is the guarantee" is not quite true**
**Categories:** refactor_safety. Three agents got running state into both codec halves through a
file-local `thread_local!` with no signature change and a clean build. An explicit
`carried: &mut u64` parameter *is* flagged, at 2 library and 34 test call sites. The signature is
most of the guarantee; the tests are the rest.

### Minor and Nits

Twenty-eight between the five. Acted on: the `quiet` arm's comment says "every read agreed" while
all 137 of its comparable reads disagree, because the loop overwrites the reference and leaves the
observation's bases; record 9 is a one-base locus carrying a witness naming offsets 5 and 6, a
record no producer emits and the shape `a_rich_record`'s own doc warns against; the 300-read builder
is a verbatim second copy of C2's, and only one copy carries the assertions that say what it is for;
the same five-line compare loop is written three times; the head-walk loop `walk_keeping` exists to
remove is open-coded twice more inside C3's own tests; a refusal inside the harness cannot say which
of six patterns was running; the scribble runs one pattern where the oracle runs six; no C3 walk uses
a layout with unknown trailing fields — the exact configuration the mean-coverage trap would arrive
in; `walk_keeping`/`keep`/`built`/`whole`/`scribbled`/`located` are bare participles; `quiet` and
`deep` are back after C2 removed them; and the new doc heading is a twelve-word sentence stating a
one-off experiment's tally where no test keeps it honest.

## 6. Out of scope observations

- **The commit added `proptest-regressions/ng/psp/record.txt`**, whose only entry is a seed recorded
  while the author's *deliberately injected* defect was in the tree. Checked in, it reads as evidence
  that this property once failed for a real reason, and it replays for ever. Two agents flagged it
  independently.
- **`OffsetBase::after` reading the previous record's *end* instead of its start is caught by no C3
  test** — the fixture writer and the walk share that function, so they stay in step. Only C2's
  fixture-anchored test sees it. A thin spot before Milestone E moves this code.
- **`any_record_round_trips_exactly` pins `LocusKind::Generic`**, so no property test in the module
  ever varies the locus kind. A C1 coverage gap, and the reason M3 has no test anywhere.
- **The test module should not be split.** Judged against the architecture doc's assignment and the
  crate's own convention rather than a line count: `record.rs` is the sixth largest of ~60 ng files
  and all five larger ones keep tests in-file; 123 ng files use an in-file `mod tests` and the one
  exception is a five-file directory module. C3 adds no third concern.

## 7. What's good

- **The oracle is anchored to the fixture, not to a second walk** — which is precisely what C2's M9
  asked C3 to be. A decode returning a wrong value turns `53 passed; 18 failed`.
- **A refusal and a wrong value are separable from a log line alone**, measured both ways: a refusal
  arrives as `record 3 builds: the record's observation-count, 6 bytes in, is unreadable`, a wrong
  value as an `assert_eq!` naming the record. Nothing is swallowed.
- **The skipping walk's own state is pinned** — dropping the base advance from the skip branch fails
  three of the five.
- **The `0xff` scribble is a genuine corruption, not a no-op**: making the harness decode the skipped
  bodies anyway fails with `the record's reference-bases, 5 bytes in, is unreadable`.
- **Rebuilding a twelve-record fixture in every test is not a performance problem** — the module runs
  in 0.03 s with the proptest rebuilding it 256 times inside that. The question was worth asking and
  the answer is a number.
