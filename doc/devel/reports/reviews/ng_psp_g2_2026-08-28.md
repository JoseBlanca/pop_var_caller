## 4. Top 3

1. **M1 — nothing held the claim the type exists for.** All seven new tests check only that a
   declined record's body came back `None`, which a decode-then-discard implementation satisfies
   exactly as well.
2. **M2 — a selective walk accepts damage a full walk refuses, and nothing said so.** Correct by
   design; the missing warning is the finding.
3. **M3 — the predicate test could not fail on the half it names**, because every record in the
   shared fixture reads zero for the field the predicate reads.

## 5. Findings

### Major

**M1 — nothing holds "a declined record's body is never decoded".** *Category: reliability.*
`walk.rs`. Mutating the skip branch to decode the body and discard it left all 355 tests green.
The mutant is not equivalent: on a file whose *body* is unreadable it refuses where the real code
walks past — and the fixture that separates them was already in the file.

**M2 — a selective walk is a materially weaker reader of damage than a full one, and the type's
doc — which lists three consequences of the skip — does not say so.** *Category: reliability /
smells.* The two agreements between a record's head and its body are made while the body is
decoded, so a declined record never reaches them. Measured by the agent at block level: of 147
single-byte corruptions a full walk refuses, a walk declining every body accepts 108. **The
cohort's first pass is precisely a walk that declines most bodies**, and "it walked without an
`Err`" does not mean the sample read back sound.

**M3 — `the_first_passs_predicate_keeps_only_what_varies` cannot fail on the half it names.**
*Category: reliability.* `a_record` copies its observation from its own reference bases, so all 40
records read `non_reference_reads == 0` and the predicate is constant-false. Mutating
`read_record_head` to return `0` for that field failed 20 tests — this one was not among them.

**M4 — `SelectiveIter::current_block` is untested and drops the `first_block` addend silently.**
*Category: reliability.* This is G1's own M3 recurring on the accessor G2 added: every test of it
starts at block 0, where the addend is a no-op.

**M5 — neither hostile-input sweep reaches the new entry point.** *Category: extras.* The agent
ran the byte-flip sweep with a declining predicate — `opened=400 full_refused=399
sel_refused=399` — so it is clean today and the gap is regression protection for the branch a
damaged file reaches furthest into.

### Minor

- **`#[derive(Debug)]` on `SelectiveIter` is inert for every real predicate**, since closures are
  not `Debug` — so the type looked printable in rustdoc and was not, and one agent hit it: it
  could not write `expect_err` in a test.
- **`RecordHead` was re-exported from a module that does not own it**, when `mod.rs` already
  re-exports it publicly. The re-export was honest in intent — the guard test's subject is
  decoding, not naming a plain-data head — but it minted a second private path for a public type,
  which `mod.rs`'s own comment exists to prevent.
- **Three hand-forwarded accessors on `SelectiveIter`, with nothing to make a fourth surface** —
  the same drift `step` was written one screen earlier to prevent, and no way back to the inner
  walk.
- **`only_where` and `SelectiveIter` are named for the filter the type's own doc spends two
  paragraphs denying**, and a name is read at every call site while a doc is read once.
- **Arch §4.1 still sketched the shape this step deliberately did not build** — an infallible
  `records_where`, no `only_where`, no `SelectiveIter` in §1's tree. G1's review filed the same
  class of drift and G1's fixes updated §4.1; **it went stale again one step later.**
- **Untested paths:** `records_where`'s `Result` (raised at construction, predicate never called),
  and `records_where` on a psp with no records.

### Nits

The wrecked-block preamble is now written three times. `the_first_passs_predicate…` is a typo.
The `RecordHead` re-export sat inside the alphabetised `use` block. `RecordIter::next` always
yields `record: Some(..)` yet its item type still carries the `Option`, so every full-walk caller
writes `.expect("a body")` — pre-existing from D3, but G2 is what puts two walk types with one
item type in front of a caller.

## 6. The author's own numbers

Re-derived independently by one agent with a scratch walk: `blocks=8 heads=40
kept_every_third=13 heads_with_nonref=0 per_block={0:5,…,7:5}`; and 355 + 4,551 filtered = 4,906
= 4,892 + 14 ignored, with the diff adding exactly seven `#[test]`s, so 348 and 4,885 check out
too. **All correct.**

Three prose claims were reproduced and hold: a declined record costs its head and a pointer
advance; the live set is exact after a decline (structurally — the head applies the chain-id
changes *before* the predicate is called); and skipping saves building but not decompressing —
**stronger than stated**, since the head's own `take(body_bytes)` needs the body's bytes in the
buffer.

## 7. On the design questions put to the reviewers

- **The `only_where` builder is right.** Keeping one type would put an `F` in the return type of
  all three entry points; one predicate-method per starting point writes the same line three times
  and still leaves a fourth entry point to repeat it.
- **`step` genuinely cannot drift**: `next_record_where` occurs exactly once in the file, and the
  `&mut self.want` comment is accurate about the mechanism.
- **G3 and G4 are untouched** by G2's shape — `replace_trailer` is a free function over a path and
  `append` is a writer constructor; neither reads records. The forward risk named is Milestone H,
  where a question added to `RecordIter` would be silently absent from the selective walk.

## 8. What's good

- **The chain-id live-set test is discriminating and builds its own fixture** rather than reusing
  the empty-`chain_ids` shared one — it does not repeat G1's M7. Its one gap is that all three
  records sit in one block, so the reset at a block boundary is not seen under a predicate.
- **No panic escapes, no unbounded allocation, no record after a refusal** on either walk shape.
- **`records_where`'s `Result` is raised in the right place** — at construction, with the
  predicate never called.
