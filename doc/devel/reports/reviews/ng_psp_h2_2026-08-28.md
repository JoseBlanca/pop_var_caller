## 3. The finding that matters

**The killed-writer test does not do what its doc says, and the doc's claim is the reason the test
exists at all.** Three independent measurements, from two agents:

- **The child is not mid-write when it is killed.** Its 80,000 pushes take about **5 ms**; the
  parent kills at about **12 ms**. Instrumented with a marker file the child touches when its push
  loop ends: the marker existed in **25 runs out of 25**. The child had finished and was asleep.
- **The file the kill leaves ends on a block boundary**, never inside a block — 233 whole blocks,
  the chain ending exactly at the file's last byte, five runs out of five. This is structural:
  `PspWriter` hands each block to the `BufWriter` in one `write_all`, the buffer is the default
  8 kB, and this fixture's blocks average about 57 bytes, so a flush can only land where a
  `write_all` ended.
- **The state is reachable from inside the process.** A `PspWriter` given 58,251 pushes and then
  **dropped** leaves a file **byte-identical** to the killed one.

So the sentence *"`SIGKILL` … the file can end anywhere at all, including part-way through a
compressed block … That state is unreachable from inside the process"* is false in both halves.

**And the mutation table's third row is wrong.** *"the child calls `finish` after its 80,000
pushes — changed no behaviour"* is not a no-op: it fails **40 of 40** standalone runs and **7 of
10** under the parallel suite. The test was a race, and the row recorded the race's outcome on one
run as a property.

⚠ **I ran that mutation myself and saw it pass.** That is what a flaky test looks like from
inside; one run is not a mutation result.

## 4. The other findings

- **Major — the truncation sweep folds `NotAnNgPsp` into its `Incomplete` counter.** Mutating
  `read_the_head_magic_of` to return the wrong four bytes flips **3,694 of 3,742** cuts to
  `NotAnNgPsp`, and the sweep still passes — while the sibling test added in the same commit exists
  to forbid exactly that misdiagnosis.
- **Major — every way the child can fail is reported as the one cause it usually is not.** A stale
  `--exact` filter makes the SIGKILL assertion fire with a message about destructors and flushing.
  Reproduced. The report's §8 predicted a different message, six lines further down, that is never
  reached.
- **Minor — the wait threshold was eight footers (384 bytes) against a header of 3,136**, so it
  did not guard what its message said.
- **Minor — `!while_doing.is_empty()`** would have been satisfied by a single space.
- **Minor — the walk was configured from a fixture builder** rather than from the file under test.
- **Minor — the child parked in an unbounded loop**, orphaning a process if the parent died.
- **Minor — a drop does not put "everything the writer had produced" on disk.** The records inside
  the open block are not in the `BufWriter` at all, so `Drop` cannot flush them: measured on F3's
  own fixture, **5 of 40 records — 12.5 % — never reach disk**, and the cut is at a *block*
  boundary, not a record boundary.
- **Minor — "the count is asserted, so it cannot go stale" is wrong.** The assertion is
  `incomplete == whole.len()`, which is self-referential; nothing pins 3,742 or 3,136.

## 5. What was applied, and what is still open

**Applied** (committed on top of `73e92f04`):

- the stale-filter Major: the child's stderr is piped and the assertion names every cause it cannot
  distinguish — reproduced before and after;
- the `NotAnNgPsp` Major: counted apart and asserted zero;
- the mid-block claim: corrected in the doc, and the block-edge property **asserted** so a change
  to the writer's buffering says the premise moved;
- the wait threshold tied to the header's length;
- `while_doing` pinned to its exact phrase;
- the manifest taken from the file under test;
- the child's park bounded;
- the naming, the two banned emphasis clauses, and the undefined terms.

**Also applied, in the second fix pass:**

- **the child now pushes until it is killed**, bounded by the contigs' lengths as well as by a
  deadline, and **touches a marker only if it stops of its own accord** — which the parent requires
  to be absent. Twenty runs out of twenty pass; a mutation that writes the marker while the child
  is still pushing fails on that assertion alone, isolating it from the signal check;
- **the truncation sweep now requires its fixture to have blocks** — it passed unchanged on a psp
  with none;
- **`walk_from`'s own `Io` arm carries a note saying it is untested and why**, rather than waiting
  to be rediscovered: `Seek` on a regular file fails only for an offset `SeekFrom::Start(u64)`
  cannot express, and the write-only descriptor that gives the read its `EBADF` seeks perfectly
  well, which is exactly why it works for the read;
- the implementation report's §2, §3.1, §6 and §8 are corrected, including the mutation row.

**Still open:**

1. **The `PROJECT_STATUS` entry and the two commit messages of `73e92f04` and `955dd20a` repeat
   the false mechanism.** Git history is not rewritten here; the correction lives in the
   implementation report and in this one, and the status entry is rewritten in the fix commit.
2. **No fixture produces a mid-block cut**, so that state is covered only by the truncation sweep.
   Reaching it would need one compressed block larger than the `BufWriter`'s 8 kB.
