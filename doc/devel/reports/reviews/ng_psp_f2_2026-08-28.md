## 6. Findings

### Major

**M1: [footer.rs](../../../../src/ng/psp/footer.rs) — every accepted footer in every test has an
empty trailer**
**Categories:** reliability.

Every `Footer` reaching an `Ok` had `trailer_bytes: 0` — the three round-trip shapes, the
widest-value fixture, the `a_footer()` helper, and all three non-abut cases, which spread it. The
one non-zero value in the file sat on an overflow path and was consumed by an `Err`.

**A trailer that holds something is what every finished psp has** — it is the writer's closing
payload (spec §3.4). So the normal shape was the one never round-tripped, and two wrong abut
rules passed the whole suite: one folding `trailer_bytes` into the comparison, one checking only
when the trailer is empty.

**M2: [footer.rs](../../../../src/ng/psp/footer.rs) — the no-`..` destructure forces a new field
to be *mentioned*, not written**
**Categories:** refactor_safety.

Adding a seventh field to `Footer` gives six compile errors, as the commit message claims. But
the remaining signal is one `unused variable` warning whose own help text reads
`help: try ignoring the field: 'trailer_checksum: _'`. **Taking rustc's suggestion leaves clippy
clean and all 14 tests green**, with a field that exists on `Footer`, is written into no file,
and decodes as 0 from every file. Nothing tied `FOOTER_BYTES` to the field *set*: the width test
read fields off a value, and reading fields is undisturbed by a struct gaining one.

### Minor

Two of three refusals never said the file was damaged, though the type's own doc makes the
message what carries the instruction (errors); the two overflow checks could report each other's
section with nothing pinning it, because no fixture made both fail at once (reliability,
idiomatic); nothing tested that arbitrary 48 bytes never panic — the module's standing rule, and
a class it has shipped once already (reliability); `no_byte_of_the_footer_is_ignored` compared
each flip against the footer it *started from* rather than against what the pristine bytes
decode to, so a decoder masking a byte still passed whenever the fixture's value had no zeros
there — masking `n_blocks`' top byte was caught, masking `index_checksum`'s was not (extras);
`FileSection` was public in an error variant without `#[non_exhaustive]`, one line from an enum
that has it (errors); `SectionRunsOffTheEnd` named a check the same function documents it
*cannot* make, and F4 has to map that variant (naming); `SectionsDoNotAbut` used a word appearing
nowhere in the spec, arch or plan, and it reaches the operator (naming); `FileSection::Index`
was the only link in the chain spelling it other than "block index", under a test called
`every_section_has_one_spelling` (naming); a file shorter than 48 bytes is unrepresentable at
this level and the "what it does not check" paragraph did not say so (defaults); `NotAFooter`
renders `expected` as text but `found` as hex, so the commonest wrong file reads
`[50, 53, 50, 45]` where `PSPE` would name it (errors).

### The author's own numbers

**N1. "Moving the magic check after the offsets is caught by three tests" — it is caught by
one.** The mutation that produced the 3 **deleted** the check rather than moving it, making it a
duplicate of the row above it. Re-run with the check genuinely moved: one test,
`the_magic_is_checked_before_the_offsets_are_believed`. The property is real — the moved check
returns the damage class where it should return *never finished*, and F4 maps those apart — so
the number was wrong and the claim was not. **`PROJECT_STATUS.md` already said it in the
singular; the report and the commit message were the two that disagreed.**

**N2.** The report said `mod.rs` re-exports "the five new names"; it is four.

**N3.** "The width is now asserted three ways"; it is four.

Everything else re-derived clean: 48 bytes; the golden literal decoded by hand field by field;
3→14 footer tests; 4,811→4,822 library; and nine of the ten injected defects scored exactly as
claimed.

## 7. Out of scope observations

- **A hostile-input sweep found nothing.** 200,000 random 48-byte tails, half carrying the real
  magic: `not_a_footer=100000, overflow=75161, no_abut=24839`, none accepted, nothing panicking.
  Three hostile-but-well-formed shapes *are* accepted — an index at byte 0 over the header, both

  function's own "what it does not check" paragraph, and the delegation was verified real.

## 9. What's good

- **The three checks are the right three.** Read field by field, a single-byte change to
  `index_offset`, `index_bytes` or `trailer_offset` always breaks the abut equality; the other
  three fields each have an owner elsewhere, and the reviewer verified the one the doc cites —
  `decode_index` does refuse a buffer it has not exhausted. No check is over-strict for the spec
  as written.
- **The vocabulary trap was handled.** Every `trailer` this commit adds means ng's trailer and
  never production's tail, and the file repeats the warning at the point of use.
- **The loop-plus-cursor in `encode_footer` beats production's five explicit assignments** —
  production repeats ten bounds that must agree; the loop authors only the order, and swapping
  two entries fails five tests.
