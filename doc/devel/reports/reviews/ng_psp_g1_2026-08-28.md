## 4. Top 3

1. **B1 — `records_from` silently drops records when two blocks share a first position.** Wrong
   results, no error, on a file shape the format documents as legal.
2. **M1 — the catch-all arm makes *the file is corrupt* the default class for every future
   `BlockReadError`**, which is exactly the flattening this step exists to prevent.
3. **M3 — the block ordinal a failure reports is only ever tested from a walk that started at
   block 0**, where the addend that makes it absolute is a no-op.

## 5. Findings

### Blocker

**B1 — `records_from` skips a block when two blocks share a first position.**
*Categories: idiomatic/structure (filed), reliability (convergent).* `reader.rs:260`.

The search was `partition_point(|entry| entry.first_position <= at)` and then one back, which
reads as *the last block starting at or before `at`*. On a run of entries sharing one position
`<=` steps past all of them, so the walk enters the run at its **end** and the records the earlier
blocks hold — whose start is exactly `at` — are absent, with no error.

`index.rs` documents this shape as one the index exists to accept ("Two blocks may share a first
position, and the rule is written for it") and tests that a psp carrying it decodes. Both agents
reproduced it through the public surface with `block_byte_ceiling = Some(1)`: on a three-record
file, `records()` gives three records and `records_from` at the shared position gives two.

**And the rule was wrong in a second way neither reproduction needed.** Even with no run of equal
positions, a block's *last* record may begin on the base the next block begins on — the same byte
ceiling produces it — so the block whose first position equals `at` is not necessarily the first
one holding a record at `at`.

### Major

**M1 — a catch-all on `BlockReadError` makes *rebuild the file* the silent default.**
*Categories: errors (filed), idiomatic (convergent).* `walk.rs:136`, `walk.rs:69`.

`refuse` matched three named classes and then `damage => CorruptBlock`. `BlockReadError` is this
crate's own enum, so an exhaustive match is legal — one agent wrote one and the suite stayed
green — and a variant added tomorrow would otherwise take the *rebuild the file* instruction with
no compile error at the place that has to choose. One variant is already misrouted in waiting:
`BufferCeilingUnderTheBuffer` is a caller's mistake and would have arrived as "block N is
corrupt".

**M2 — the error chain told an operator to raise a ceiling no `PspReader` had.**
*Category: errors/defaults.* `mod.rs:385`, `block.rs:1940`.

`RecordLargerThanTheReaderAllows`'s own doc said the message deliberately withheld *raise the
ceiling* because a `PspReader` cannot. Its cause said it anyway: the agent printed the chain and
the cause ends "; raise the ceiling to read it". `with_a_buffer_ceiling` existed only on
`BlockStream`, which nothing in `reader.rs` or `walk.rs` called. Spec §7 makes raising the ceiling
the *required* action for this class, so the instruction as delivered could not be followed.

**M3 — the block ordinal a failure reports is unpinned.** *Category: reliability.* `walk.rs:139`.

Both failing-walk tests started at block 0, where `first_block + x` and `x` are the same number.
Deleting the addend left 337 passed. Wrecking block 5 and walking from block 4 shows the
difference: the mutant says 1 where 5 is right — an operator sent to a block that read back
perfectly.

**M4 — `CorruptBlock { block }` was documented as an index into `block_index()`, and in one
reachable case is out of range.** *Category: idiomatic/structure.* `mod.rs:363`.

The field's two sentences contradicted each other: the "block that never began" the second
describes can be one past the last entry the index has. Reproduced with two junk bytes between
the last block and the index — `block: 8` on a file whose entries run 0..=7 — so a caller
following the doc and writing `block_index()[block]` panics on exactly the file the error is
about. The path had no test.

**M5 — two functions called `walk_from`, three adjacent `u64`s, passed in opposite orders.**
*Categories: errors/naming (filed), idiomatic (convergent).* `walk.rs:36`, `reader.rs:274`.

Swapping the ordinal and the offset compiles and gives `CorruptBlock { block: 3136 }` on an
eight-block file; swapping the two byte offsets gives `Take(0)` — **a silently empty walk, with
no error and no failed seek**, which is a sample read as covering nothing. Ten of thirteen tests
caught the first; nothing caught the second.

**M6 — the record-level *upgrade the reader* arm had no test.** *Category: reliability.*
`walk.rs:151`.

`a_manifest_this_build_cannot_read_asks_for_a_newer_reader` reaches that class through
`BlockStream::new` inside `walk_from`, which is a different arm a hundred lines earlier. Rewriting
the record-level arm to `CorruptBlock` left the suite green — and that class's trigger, a newer
writer, is the one here that is expected in normal operation rather than on damaged input.

**M7 — `RecordIter::live_reads` is public, has no caller and no test, and the shared fixture
cannot give it one.** *Categories: reliability (filed), idiomatic (convergent).* `walk.rs:114`.

Every observation in `a_sample` carries an empty `chain_ids`, so an implementation returning the
block's opening set, a stale set, or the right set all give the same answer. That is the second of
Milestone F's four shapes — a fixture where several wrong implementations agree — and chain-id
reconstruction is, per arch §1, where the silent failure lives.

**M8 — the `FileEndsInsideABlockLength` arm, which §3.4 calls "the one case that needs care", was
never reached by a test.** *Category: reliability.* `walk.rs:139`. Making it identical to the
general arm left the suite green.

### Minor

- **`UnsupportedRecordEncoding`'s message carried neither the instruction nor the field**, while
  its chain printed the same sentence twice (`mod.rs:405`).
- **`damaged_by`'s `reason` restated its own cause verbatim** (`reader.rs:344`, `:448`), so a
  chain read as a fault in the printer.
- **`blocks_read()` was named for what its own doc says it is not** — it forwards
  `BlockStream::blocks_begun` (`walk.rs:124`).
- **A `records_from` caller could not learn the block ordinal its own doc told it to add**
  (`walk.rs:98`).
- **`NoSuchBlock`'s field names said the shape, not the value** (`mod.rs:420`).
- **`Damaged`'s cause was `Box<dyn Error>`**, and the step's own test had to downcast it
  (`mod.rs:346`).
- **The guard test checked less than its doc claimed, and a braced `use super::{block::…}` walked
  past it** — verified: it compiles and the guard passes (`reader.rs:839`).
- **The arch doc's module tree and reader interface were behind the code** — no `walk.rs`, still
  `blocks()`, still an infallible `records()` (`arch §1`, `§4.1`).
- **Three untested corners of `records_from`'s range**: a coordinate past every block, a contig
  the file does not carry, and `records_from_block(0)` on a psp with no blocks.
- **Nothing in the new file walked a *damaged* psp** — the module's only malformed-input test
  stops at `open`.

### Nits

`read_the_head_magic` reads oddly at first sight and is the right call (verb, cursor moves,
consistent with `decode_the_body_of`). The `PspReader` field was `blocks` while its accessor is
`block_index()`. The footer decode/patch preamble appears in three tests. A block ordinal is
`usize` at the API and `u64` in the errors, so `as u64` appears at every hop. An I/O failure
inside a walk renders as "read while reading a block's compressed bytes".

## 6. The author's own numbers

Every figure in the G1 report and commit message describing this work was re-derived. **All
correct**: 337 against 324 `ng::psp` tests; 4,874 against 4,861 library tests; 40 records and 8
blocks in the fixture; 707 lines of `walk.rs`; twelve defects injected and twelve caught; the
400,000-base record; the 512 kB ceiling; the 10 records of the two blocks before the wrecked one.

Three prose claims were reproduced and hold: an unbounded stream reaches a ninth block on an
eight-block file and zstd answers `Unknown frame descriptor`; a fault in the four introducing
bytes names one block later; two blocks may share a first position — **and checking that last one
is what found the Blocker**.

One claim overclaimed: "the property survives the feature that would have ended it". What survives
is the substring assertion, not "nothing that inflates a frame is callable from here" —
`reader.rs` now reaches `BlockStream` through `walk`.

## 7. Robustness

Both hostile-input sweeps came back clean on the unmodified tree: 400 psps with one to four bytes
flipped inside the blocks, and 300 with a block index whose offsets point at arbitrary bytes and
whose checksum was recomputed so `open` accepts it. No panic, no hang, no record handed over after
a refusal. Both are now tests.

## 8. What's good

- **The `reader.rs` / `walk.rs` seam is right**, and the agent that judged it said so plainly: it
  is the same line arch §1 already draws, not an artefact of the guard test, and it would be the
  right split without it. G3 and G4 are unobstructed.
- **`records_from`'s two ⚠ paragraphs** — that the walk starts before the coordinate, and that it
  selects on where records start rather than on what they span — are the right things to have
  written down, and the test that pins both halves of the spanning-record case is the shape this
  milestone wants.
- **The bound at the index offset** is the correct mechanism and is proven by a test that would
  fail without it rather than asserted.
- **Twelve injected defects, twelve caught**, every anchor asserted to match exactly once first.
