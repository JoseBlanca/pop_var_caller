# Code Review: ng psp D1 — cut blocks on the genomic grid
**Date:** 2026-08-27
**Reviewer:** rust-code-review skill (orchestrator), eight category sub-agents, each in its own git worktree
**Scope:** commit `a5eccee9` on `ng-psp-encoding` — the block cut, the block head, and the payload a compressor will be handed
**Status:** Request-changes

- **Reviewed against:** `a5eccee9`, branch `ng-psp-encoding`.

- **Out of scope:** the frozen production tree `src/psp/`; the rest of `src/ng/psp/` except the

  `ref.fa.repeats.parquet` and are pre-existing; `benches/psp_writer_perf.rs:386`, which panics

- **Categories dispatched:** all eight — `reliability`, `errors`, `naming`, `defaults`,

**What the eight did.** Between them: **72 mutations** applied and run, **1,400,000 fuzzed
inputs** to the two parsers, **501,434 builder pushes** across 40,000 random record streams, and
an independent re-derivation of every number in the commit and the report.

## 2. Verdict

**Request-changes. Two Blockers and nine Majors — and neither Blocker is a defect in the cut.**

Both are properties the code *has* and no test *holds*, and both were found by more than one
agent independently:

- **nothing held the cut to a record's start.** Changing `region.start` to `region.end` in the
  one line that decides a block passed all 21 tests, because no fixture in the file had a record
  whose span crossed a grid multiple. The harm is silent by construction: every file still reads
  back self-consistently, and only a cohort read across samples would notice that a sample
  carrying a deletion cut where its neighbours did not.
- **`BlockRecords::split` handed a whole-block caller `Truncated`** — the class whose instruction
  is *fetch more bytes*, about a block already entirely in memory. This one *is* a defect, and it
  is [the C2 review](ng_psp_c2_2026-08-26.md)'s Blocker one level up; `record.rs` already carries
  the remedy for a record inside a bounded body and `block.rs` had no equivalent.

**The parsers came out sound, and that is the main positive result.** 1.4 million arbitrary-byte
inputs produced no panic, no arithmetic overflow, and no allocation sized from a declared length —
a head declaring `record_count = u64::MAX` in front of three bytes allocates nothing, which is
spec §8's trap avoided rather than survived.

**One number in the commit message is wrong** — a spec figure quoted at the wrong grid size — and
every other number in the commit and the report reproduced.

## 4. Top 3 priorities

1. **B1 — the cut's one decision is untested**, and the failure mode is a grid that stops
   aligning across samples without any file being invalid.
2. **B2 — a whole-block caller is told to fetch more bytes**, which is a retry that never ends;
   this is the same defect class the previous milestone's Blocker was.
3. **M9 — the per-block reset has no compiler-flagged home**, and Milestone E's chain-id live set
   is exactly the shape that exploits it: a field added to `RecordEncoder` and initialised in its
   constructor alone builds clean, is never reset, and writes a file that is wrong from every
   block's first record.

## 5. Findings

### Blocker

**B1: [block.rs:394](../../../../src/ng/psp/block.rs) — nothing holds the cut to a record's *start*; a record straddling a grid multiple appears in no fixture**
**Categories:** reliability, refactor_safety, smells — **three, independently.** **Confidence:** High.
`cell_index: region.end.get() / …` compiles and gives `21 passed; 0 failed`. Every fixture is a
span-1 record or one whose span stays inside its cell; the whole-cut oracle's widest record ends
18,004 bases into a 100,000-base cell, and collapsing its span variety to a constant also leaves
the suite green. Measured behaviour change: on `[a_record(0, 99_998, 5), a_record(0, 99_999, 1)]`
the shipped code gives one block and the mutant gives two.

**B2: [block.rs:193](../../../../src/ng/psp/block.rs) — `BlockRecords::split` forwards `Truncated` to a caller holding the block entire**
**Categories:** errors. **Confidence:** High.
The type's own doc says it is "for a caller holding a block entire", so there are no further bytes
to fetch and the retry is a fixed point. Applying the conversion *as a mutation* also left all 21
tests green, so the class was pinned in neither direction.

### Major

**M1: [block.rs:141](../../../../src/ng/psp/block.rs) — a varint fault misfiled as `Truncated` passes all 21 tests, and the arm is a wildcard where `record.rs` matches exhaustively**
**Categories:** errors, reliability, extras — **three.** Ten continuation bytes are
`VarintError::Overflow` and a fixed point: appending more never changes the answer, so misfiling
it is a reader that spins. Only the *other* direction was tested. The wildcard also leaks the
codec's own "the 10-byte cap" wording into a format error, where `record.rs` deliberately rewords
it.

**M2: [block.rs:63](../../../../src/ng/psp/block.rs) — `record_count`'s "never zero" is a doc comment, so `encode` writes bytes `decode` refuses**
**Categories:** idiomatic, errors. `BlockHead { …, record_count: 0 }.encode()` succeeds — its doc
says "It cannot fail" — and produces `[1, 172, 2, 0]`, which this file's own decoder rejects.
Production's `.psp` makes the same invariant a checked one, so ng was the outlier.

**M3: [block.rs:348](../../../../src/ng/psp/block.rs) — the one refusal path with no rollback is the one no test reaches**
**Categories:** errors, reliability. The existing rollback test's codec refusal is at start
300,000, which is always a different grid cell, so it always lands on the *cut* path. Simulating
the encoder's promise breaking by one byte left 21 tests green while producing a block carrying a
stray `0xff` between two records with its head still declaring two. Counting the record before
encoding it is worse than an off-by-one: it also poisons the order check, so the *next legitimate*
record is refused.

**M4: [block.rs:321](../../../../src/ng/psp/block.rs) — `from_manifest` is tested only with no ceiling**
**Categories:** reliability. Replacing the call with `Self::new(grid, None)` left 21 green: half
the declared cut rule reached the builder untested.

**M5: [block.rs:321](../../../../src/ng/psp/block.rs) — `from_manifest` ignores the manifest's declared field layout**
**Categories:** extras. The constructor's own doc invokes the append path, where the manifest is
*not* this process's own; `RecordLayout::from_manifest` next door is exactly the check and was not
called.

**M6: [block.rs:297](../../../../src/ng/psp/block.rs) — a zero byte ceiling is accepted where `header.rs` refuses it**
**Categories:** defaults, idiomatic, extras — **three.** `new`'s own doc states the rule it is
breaking — "`Manifest`'s fields are public and a caller can build one that never met that check" —
and applies it to the grid only. Measured: `new(A_GRID, Some(0))` is accepted and four records give
four blocks of one. A side finding: `header.rs`'s stated reason, "closes every block empty",
describes something this code cannot produce.

**M7: [block.rs:271](../../../../src/ng/psp/block.rs) — nothing pins "no ceiling" as the default**
**Categories:** defaults. Storing `block_byte_ceiling.or(Some(1_048_576))` — the value spec §12
question 2 leans toward — left all 21 green, because every fixture holds tens of tiny records. On
a grid cell holding 2,070,000 bytes the mutant cuts two blocks where the committed code cuts one.
The one configuration value the spec says is still open was the one no test locked.

**M8: [block.rs:74, 288](../../../../src/ng/psp/block.rs) — no property test, on two round-trip laws, with `proptest` already a dev-dependency**
**Categories:** reliability. `BlockHead`'s round trip was covered by one hand-picked triple;
`BlockBuilder`'s stronger law — records in, the same records out, whatever the grid and the
ceiling — by fixtures whose grid was always 100,000 or 1,000. A randomised span would have found
B1 in its first hundred cases.

**M9: [record.rs:1190](../../../../src/ng/psp/record.rs), [block.rs:268](../../../../src/ng/psp/block.rs) — the per-block reset has no compiler-flagged home**
**Categories:** refactor_safety. Spec §3.2 requires every running difference inside a block to
restart, and plan E1 restates the chain-id live set at each block start. Adding
`live_chain_ids: Vec<u32>` to `RecordEncoder`, initialising it in `for_block` and leaving
`start_block` alone: clean build, 21 passed. The same one level up in `BlockBuilder`. The file
already contains the shape that works — a field added to `OpenBlock` is `error[E0063]` at
`open_at`, because that literal is exhaustive.

### Minor and Nits

Thirty-one between the eight. The ones acted on: `Truncated`'s `field` and `bytes_in` were
asserted nowhere, and hard-coding both to constants passed; `ContigOutOfOrder`'s message passes
its two contigs positionally and swapping them passed, leaving a refusal that describes a legal
write; the ceiling's `>=`/`>` boundary and its exclusion of the block head are both documented
decisions and neither was pinned; `BlockWriteError` mixes a constructor's only fault with faults
only `push` can raise; `accept` absorbs an unreachable `None` with `if let`, the one arithmetic in
the file whose failure is quiet; `BlockHead::encode` reads its fields by name, so a field added to
the head is flagged at every reader and not at the writer of its bytes; three of `BlockBuilder`'s
field names are bare participles the checklist names outright, and `closed` holds bytes;
`BlockCell` names its containment backwards; `BlockHead::decode` returns an unnamed `(Self,
usize)` against a decision `record.rs` wrote down in the opposite direction; `BlockRecords` does
not say who owes the record-count check; the ceiling default is a bare `None` at four sites with
no named constant where the grid's is a documented `pub const`; four sites assemble a default
manifest by hand; and `a_record`'s doc claims a fixture property that is not merely unheld but
unachievable.

## 6. Out of scope observations

- **`block.rs` should become a directory when D2 and D3 land**, named by what the files own
  rather than split by line count.
- **⛦ Spec §12 question 3 says the accumulate-across-empty-spans rule *ships***; the commit and
  the report read it as leaving the rule itself open, where it leaves only its threshold open.
  `Manifest` has no field for it and the plan's D1 does not list it. **An owner decision for
  Checkpoint D.**
- **Nothing checks a file's declared field list against `record_fields()` at the writer**, so a
  hand-built `Manifest` can produce a file whose records do not match its own declaration. Fixed
  here for `from_manifest`; the same gap will exist at F3's `create`.
- **`record_count` is read unbounded** where `record.rs` bounds every declared count. Nothing
  allocates from it today; it becomes D3's when the streaming reader loops on it.

## 7. What's good

- **The parsers are sound under fuzzing, and the two properties D3 needs held on every input.**
  Every strictly shorter prefix of a decodable head came back `Truncated` — never `Ok`, never
  `Malformed` — on 935,103 successes; and `Malformed` never became anything else when twelve
  further bytes were appended, on 21,286 damaged inputs.
- **The refusal rollback holds byte-for-byte**: 40,000 random streams with 91,247 refusals
  interleaved produced exactly the bytes of replaying only the accepted records.
- **`walk` is what makes most of the suite bite** — it starts from the block's *declared* first
  position and asserts both that the walk consumed the block exactly and that the record count
  matched, so a head that disagrees with its records fails wherever it appears.
- **Every one of the 21 tests asserts both halves of its own name**, checked one at a time. The
  gaps are input classes no fixture reached, not assertions that could not fire.
- **The ceiling derived from a measured block rather than a guessed byte count** — the report says
  an earlier draft guessed 200 bytes and never fired, and the correction is the shape the rest of
  the file should follow.
