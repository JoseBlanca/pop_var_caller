**Date:** 2026-08-27

sub-agents, each in its own git worktree
**Scope:** commit `b9ef37e3` on `ng-psp-encoding` — `src/ng/psp/chain_ids.rs`, the `pub(super)`

## 2. Verdict

**Request-changes. One Blocker, four Majors, and the Blocker is a design decision the report
records as deliberate.**

**A `Truncated` fault left the live set half-advanced.** `read_changes` applied the record's
departures *before* it read the arrival count — so any buffer that stopped in the arrival half
returned `Truncated`, which is the class whose contract is *fetch more bytes and re-parse the
record from its first byte*. The retry then resolved the same departure positions against a set
that had already shrunk. Measured over a record that departs one read and gains one: **at five of
its six cut points the retry returned `Ok` and a read that was still covering had silently
vanished** from the live set for the rest of the block; on a second fixture, seven of nine cuts
turned a perfectly good record into `Malformed`.

That is verbatim the failure spec §8 names — *"a parse that half-advances that state before
failing corrupts every record after it, plausibly"* — and it is the sentence `block.rs`'s retry arm
quotes in its own comment. **Two of the three agents found it independently**, and one found it
with a property test on its *first* generated case, minimal input `records = [[0], [1, 2]]`.

**The test that should have caught it structurally could not.**
`a_stream_cut_short_anywhere_is_a_short_read_and_never_damage` builds a fresh reader inside its cut
loop, so it never retries: it checks the fault's *class* and never the state the fault leaves
behind, which is the only thing the class split exists to protect. Ten of ten injected defects were
caught before this review, which reads as a strong suite; this is the one class of defect it was
blind to, and it is the one that shipped.

**The codec itself is sound under 1.5 million fuzzed inputs**: no panic, no hang (slowest single
input 630 µs against a 200 ms deadline), and **nothing sized from a declared count** — the reader
never held more than 976 bytes across its four vectors on inputs up to 96 bytes.

## 4. Top 3 priorities

1. **B1 — a `Truncated` fault half-advances the live set**, and the retry it instructs silently
   drops a read.
2. **R1 — no property-based test for a codec**, in a module the checklist names explicitly, in a
   crate that already has the dependency and the precedent next door.
3. **S1 — no fixture makes either merge interleave**, so half of both merge functions is unreached
   — and the shape that reaches it is the re-entry the module says nothing may assume away.

## 5. Findings

### Blocker

**B1: [chain_ids.rs:462](../../../../src/ng/psp/chain_ids.rs) — `read_changes` half-advances the live set before it can return `Truncated`**
**Categories:** errors, reliability — **two agents, independently.** **Confidence:** High.
Measurements in §2. The stated rationale was not true of the code either: the comment said the
departures were applied there *"so the positions above indexed the set they were written against"*,
but the departure loop had already finished, and `encode_changes` binary-searches the same
pre-departure set. The eager apply bought nothing.

### Major

**R1: [chain_ids.rs:509](../../../../src/ng/psp/chain_ids.rs) — no property-based test for a codec**
**Categories:** reliability. The checklist requires generated coverage for serializers,
deserializers and round trips; this module is all three. `proptest` is already a dev-dependency and
`record.rs` already uses it twice. **Not hypothetical: the Blocker was found by a property test on
its first generated case.**

**R2: [chain_ids.rs:798](../../../../src/ng/psp/chain_ids.rs) — the truncation sweep cannot fail on the property its docstring claims**
**Categories:** reliability. Filed separately from B1 because the fix is the fixture: the code fix
alone leaves the defect re-introducible with a green suite.

**S1: [chain_ids.rs:178](../../../../src/ng/psp/chain_ids.rs) and [:223](../../../../src/ng/psp/chain_ids.rs) — no test makes either merge interleave**
**Categories:** smells. Replacing `derive_changes`' `Ordering::Greater` arm and `apply_arrivals`'
`else` arm with `panic!` leaves all 13 tests — and all 214 `ng::psp` tests — passing. Every fixture
allocates ids in walk order, so an arrival is always the largest. **A returning id sorts *below*
every id allocated since it left**, which is the only shape that reaches those arms, and the module
header puts that at 83 % of ids on the human sample and 91 % on tomato.

**X1: [chain_ids.rs:494](../../../../src/ng/psp/chain_ids.rs) — `read_changes` can return the buffer's length instead of the bytes it used**
**Categories:** extras. A surviving mutant: every fixture hands it a `Vec` holding exactly one
record's stream, so the two expressions are the same number in every test. **The count is how
Milestone E3 will find the next field**, and a wrong one does not fail loudly — it re-reads part of
this stream as the next field's bytes.

**E1: [chain_ids.rs:349](../../../../src/ng/psp/chain_ids.rs) — `expect` on the writer's hot path with no `// PANIC-FREE:` marker**
**Categories:** errors. The invariant is real and provable; the marker that says so is missing, so
a later reader cannot tell a checked call from an unchecked one.

**RS1: [chain_ids.rs:273](../../../../src/ng/psp/chain_ids.rs) — `#[derive(Default)]` is a second constructor for the per-block state**
**Categories:** refactor_safety, defaults — **two agents.** The comment justifying the one-field
struct says `at_block_start` is its only constructor. The derive is a second, and `new()` is the
path that uses it — so a field added to `PerBlockState` would be default-initialised there with no
`error[E0063]`. The reset path is still protected; the *claim* holds on only one of two paths.

### Minor and Nits

Twenty-eight between the three. Acted on: the module header and report §1 give `43.78` as the
raw-identifier baseline for both corners, when it is the deep corner's alone (the shallow one is
1.020), so the sentence reads as a hundredfold saving where the real pairings are 2.4× and 6.8×;
the restatement's 12 % is quoted "at the settled block size" when it was measured at blocks
**sixty-seven times smaller**; a symmetric change to both halves of the gap arithmetic — which
keeps the codec self-consistent while changing what every previously written file means — was
killed by exactly one test, incidentally, through a byte literal in a damage test; a departure
count of three billion against a live set of 300 was bounded only by a record *body*'s byte
ceiling, borrowed from a different container; a record that departs an id and arrives the same id
was accepted with nothing saying whether it should be; `live()` and `changes()` are readable after
a fault and report partial state with no doc saying so; both `is_empty` accessors could be
inverted without failing any of the 214 tests; `new()` on both collaborators carried no doc at all,
where the question a caller has — *must I call `start_block` before the first record?* — is exactly
the one whose wrong answer produces a file that parses perfectly; `read_changes` was 68 lines with
eleven decision points and both kinds of `u64` live in one scope; the "contrast" in
`a_blocks_first_record_arrives_with_everything_and_departs_nothing` was written into a throwaway
`Vec` and never compared; and `a_departure_costs_a_position_and_not_an_identifier` says a departure
as an identifier "would cost four bytes more" when it is four instead of one.

## 6. Out of scope observations

- **`ChainId` is still `pub type ChainId = u64`**, and arch §7's open question about making it a
  newtype is now concrete: this module carries identifiers and positions as the same type and
  defends the distinction with a private field and a doc comment. Worth closing before E3 widens
  the surface.
- **`FieldReader`'s widening is asymmetric**: `chain_ids` can build a `Malformed` but not a
  `Truncated` of its own, because `truncated` stayed private. Invisible from `chain_ids`.
- **`put_varint`, `FieldReader` and `RecordDecodeError` now serve two sibling modules** from a file
  whose name says it owns record encoding. They are the container's byte primitives. Worth deciding
  at E3 whether a `codec.rs` sibling is the honest home, rather than widening `record.rs` a third
  time.

## 7. What's good

- **1,500,000 fuzzed inputs, 0 panics, 0 hangs, and nothing sized from a declared count.** The
  reader never held more than 976 bytes across its four vectors.
- **The fuzz harness was shown able to fail three ways**, each by one edit and one run — including
  catching a semantic mutant at case 2,053.
- **Every number in the report and commit message re-derived exactly**: 3,257 bytes against
  106,166 is 32.60×, "about 300 live at once" is exactly 300, the test counts add up, and every
  percentage quoted from the specs matches them verbatim. Two figures in the *prose* were wrong and
  are in §5.
- **The `pub(super)` widening is exactly what `chain_ids.rs` uses**, with nothing surplus, and
  `mod.rs`'s two lines follow the module's stated convention in alphabetical position.
- **`module_structure` filed no findings above Nit.** `chain_ids.rs` sits where arch §1 puts it and
  imports only a peer data model and its own sibling.
- **The one place a length check and an index meet is already the bounds-checked form**, and no
  `..Default::default()`, no `..` destructuring, no manual `PartialEq`/`Clone`/`Debug`.
