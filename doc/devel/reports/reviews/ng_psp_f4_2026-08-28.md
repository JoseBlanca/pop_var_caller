## 4. Open questions and assumptions

1. **The 500 kB per-open-sample budget may not fit what an open sample holds.** The block index
   alone is ~336 kB for a whole genome (14,000 entries at 24 bytes, both measured), against zstd's
   190 kB floor and two 16 kB buffers. **H4 is where this is measured**; it is recorded because
   F4 shipped a refusal threshold carved out of that budget.

## 5. Top 3 priorities

1. **B1** — only one side of the sections rule was tested, and relaxing it opened 62 of 384

2. **M1** — the derivation behind a shipped refusal threshold cites the wrong spec section and

3. **M2** — `opening_touches_no_block` proves no block is *decompressed*, not that none is read.

## 6. Findings

### Blocker

**B1: [reader.rs](../../../../src/ng/psp/reader.rs) — the sections rule was tested on one side**
**Categories:** reliability.

`a_footer_that_does_not_account_for_the_file_is_refused_as_damaged` builds its fixture with
`trailer_bytes -= 1` — sections stopping *short*. Sections running *past* the footer were
untested. **Weakening `!=` to `<` kept all fifteen tests green**, and a sweep of every single-bit
flip in a real psp's footer went from `{Damaged: 352, Incomplete: 32}` to
`{Damaged: 290, Incomplete: 32, Ok: 62}` — **62 of 384 corruptions stopped being refused and
started opening.** One character removes the property the format rests on, and the suite said
nothing.

### Major

**M1: the window budget's derivation is wrong twice, though the number survives.**
**Categories:** extras.
It cited **§5.3** for the reader's two 16 kB buffers; §5.3 has no buffer figure, that is §4.4.
And **the 190 kB it subtracts already contains a 32 kB window** — §5.3's own first line says so —
so the window was charged twice. The honest arithmetic gives 310 kB rather than 278 kB, and 2^18
is the largest power of two under both. **A wrong derivation for a right number**, which is the
kind that survives by looking finished. It also cited §4.2 for "the fix is a setting rather than a
rebuild"; §7's table is what says that, and it says *raise the budget, **or rewrite the file***.

**M2: `opening_touches_no_block` does not show what it says.**
**Categories:** reliability, extras — both agents, independently.
It shows no block is *decompressed*: making `open` decompress the first block fails it, and only
it. But an `open` that reads **every byte of the blocks region into a buffer** without
decompressing passes all fifteen tests, and *touching* is the cost spec §6.2 is about. Showing
nothing is read needs `open` drivable over an arbitrary source; it holds a concrete `File`.

**M3: a block offset pointing into the header opened.**
**Categories:** reliability, refactor_safety.
The range check bounded offsets above and not below. An entry at byte 0 opened, and the refusal
was deferred to a corrupt block at read time — the wrong instruction, arriving after a cohort had
committed to the sample. `Header::decode` already returns the header's byte length; `read_header`
threw it away. **And the upper bound was off by one**: the fixture used `index_offset + 1`, so
relaxing `>=` to `>` — a block starting exactly where the index does — left every test green.

**M4: the allocation bound is not where it looks.**
**Categories:** reliability, refactor_safety, smells.
`vec![0u8; footer.index_bytes as usize]` is sized from an untrusted length, and the guard above it
**cannot fire**: `decode_footer` and `read_footer` between them already prove
`index_offset + index_bytes <= file_bytes`. Replacing the guard's body with `unreachable!()` left
the suite green. The bound is real; it lives in two other functions with nothing in this
signature saying so.

### The author's own numbers

**N1: the library was 4,841 before, not 4,836.** **N2: `ng::psp::` is 319 after and 304 before,
not 314 and 299** — and the report contradicted its own commit message. Re-measured at the parent
commit and confirmed.

**The ten-defect table is the first in this milestone to survive re-scoring intact** — all ten
counts reproduce.

**N3: the commit message and report describe the `tests_support` lift as part of this diff.** It
landed in the parent commit.

### Minor

`trailer()` reads the same twice only by accident — every test calls it once, when the cursor
already happens to be right, so a missing seek would return the footer's bytes on a second call
(reliability); the truncation test folds `NotAnNgPsp` into its `incomplete` counter and so does
not assert the distinction (extras); the budget the reader opened under is not stored, so an open
reader cannot say what ceiling it holds (defaults); `Damaged { reason: String }` adds a seventh
`reason: String` to a surface F3's review already routed to G (smells); and the naming set —
**`PspReader::trailer()` collides with production's method of the same name on a type of the same
name, returning a different section of the file** (naming, and the vocabulary trap's third
firing), `seek_to` (genomic there, bytes here), `head_magic` as a noun for a function that seeks
and reads, and `blocks()` returning what the spec calls the *block index*.
