## 6. Findings

### Blocker

**B1: [header.rs:1175](../../../../src/ng/psp/header.rs) — nothing states what any encoding's
cardinality *is*; every test asks the code and checks the file agrees**
**Categories:** reliability (convergent with smells' cross-category note).

`every_scheme_round_trips_with_its_own_cardinality_and_is_refused_with_the_other` opens with
`let implied = scheme.cardinality();` and checks the round trip against `implied`, so **any
wrong answer applied consistently passes it**. The only test stating the truth independently,
`exactly_two_of_the_records_fields_are_lists`, reaches only the five encodings `record_fields()`
uses.

Measured: moving `SignedVarint`, `FixedWidthInteger` and `IeeeFloat` into the `AList` arm left
the suite green at **255 passed, 0 failed**, while `a_written_header()` began writing
`cardinality = "a-list"` beside a signed varint, a 4-byte integer and an 8-byte float.

Those three are exactly what the two queued fields — a window's GC fraction and its mean
coverage — will use. A wrong answer writes a false claim into every psp header, and a later
reader driven by the manifest would look for a count where a float is: wrong bytes, no panic,
nothing failing first.

### Major

**M1: [header.rs:223](../../../../src/ng/psp/header.rs) — `cardinality` is production's word
for the other half of this idea, and both formats use the `.psp` extension**
**Categories:** naming.

Production's frozen store has *both* halves as separate types —
`Cardinality { PerRecord, PerAllele }` ([`src/psp/registry.rs:25`](../../../../src/psp/registry.rs))
and `Shape { Scalar, List, Bytes }` (`:60`) — and writes both keys into its own TOML header.
The new `FieldCardinality { OneValue, AList }` **is** production's `Shape`. Someone running
`head` on two files sees `cardinality = "per-record"` in one and `cardinality = "one-value"` in
the other: same key, unrelated meanings. This module already argues at length that its head
magic must differ from production's for precisely this reason.

**M2: [header.rs:223](../../../../src/ng/psp/header.rs) — the doc comment contradicts the code,
and the code is right**
**Categories:** naming.

Four lead sentences say "how many values of it a record holds"; `mapq-sum` is a `Varint`, so its
declared cardinality is `OneValue`, yet `encode_record_body` writes it inside the per-observation
loop — a record with five observations holds five of its values. "One value per record" is false
for ten of the twenty-two body fields. The lead sentence fifteen lines above says one thing and
the caveat below says the other.

**M3: [header.rs:262](../../../../src/ng/psp/header.rs) — a hand-written array whose length is a
number in the source, and a completeness test that cannot catch it**
**Categories:** refactor_safety.

Adding a third cardinality raises three compile errors and lets you past `ALL_CARDINALITIES`,
which stays two entries long and compiles. `the_cardinality_list_holds_every_value_the_type_has`
establishes its expected count as a literal inside an exhaustive match, so the mechanical repair
of its compile error — extend the `|` chain — leaves the `2` intact and the assertion passing.

**⚠ The identical flaw is pre-existing in `ALL_ENCODINGS` and its own completeness test**, and
the reviewer demonstrated it: with only the compiler-flagged sites repaired, the suite was 253
green while `Header::encode` wrote an encoding `Header::decode` refused — the exact failure that
array's doc comment says the two-sided rule prevents. **Out of scope for F0's fix** (§7), but
this commit copied the pattern.

### Minor

**Mi1: `FieldSpec.cardinality` is stored where it should be derived.**
**Categories:** idiomatic, smells, defaults — three agents independently.
The stored value has exactly one legal value for any encoding, and smells proved it carries no
information: serialising `field.encoding.cardinality()` instead of the stored field left all 253
tests green, because the only production caller has already proved the two equal. Meanwhile all
three `FieldSpec` fields are `pub`, so a disagreeing pair is constructible, and both smells and
defaults got one accepted by the public `RecordLayout::from_manifest` — inert only because that
function never reads the field.

**Mi2: the one test that reads a file's own bytes never sees `a-list`.**
**Categories:** smells, reliability, extras — three agents.
`a_manifest()` declares six of the eight encodings and omits **exactly the two list-shaped
ones**, so half the new wire vocabulary never appeared in any header text any test inspected.
Its own doc claimed "one field per encoding the format has".

**Mi3: `cardinality_of` is pinned only against a spelling resembling neither known one.**
**Categories:** reliability, extras.
Replacing `==` with `starts_with` left the suite green (a header saying `"one"` or `""` then
decodes as `OneValue`); so did making the match case-insensitive and whitespace-trimming. The
fallback the design forbids, reached by a different route.

**Mi4: the disagreement message can be inverted with both its tests green.**
**Categories:** reliability, errors.
Both assertions are `contains` of the ingredients, so swapping the two operands passes while
producing a message claiming `chain-id-list` "lays down one-value". Errors separately found that
dropping the declared encoding from the message also passes.

**Mi5: `a_field_that_declares_no_cardinality_is_refused` passes with `#[serde(default)]` added.**
**Categories:** errors, defaults.
The refusal then changes class — claiming the file declared `""` and losing the TOML line
number — while the assertion, `contains("cardinality")`, is satisfied by the rule name either way.

**Mi6: the unknown-spelling test's fixture name contains the bad value.**
**Categories:** errors, reliability.
The field is named `per-observation-thing` and the refused value is `per-observation`, so
`contains("per-observation")` holds even if the message stops naming the value. **This is the
substring trap the commit message reports fixing for `field-cardinality`, reintroduced in the
test next door.**

**Mi7: a field name can forge a manifest line in the header's text.**
**Categories:** extras.
Field names are validated for emptiness and duplication only; contig names *are* checked for
whitespace, a hundred lines above. A field named `evil"\ncardinality = "a-list"\nx = "` is
written by `toml` as a multi-line string, and the reviewer produced a header showing
**9 `cardinality` lines for 8 fields**, `a-list` beside a field declaring `one-value`, still
round-tripping correctly. A display forgery rather than a parse divergence — but it defeats this
commit's own asserted "one line per declared field" invariant, and readability is the stated
reason the header is text at all.

**Mi8: `RecordLayout::from_manifest` ignores cardinality with nothing saying whether that is
deliberate.**
**Categories:** defaults, reliability.

**Mi9: the implementation report cites `tmp/mutate.py` and `tmp/mutate2.py`, which are not
tracked.**
**Categories:** extras. The report's most load-bearing table rests on a citation no later reader
can follow. The numbers themselves were all reproduced independently and are correct.

**Mi10: `#[non_exhaustive]` on a two-variant enum this crate alone constructs; `cardinality` is
`pub` with all three call sites in the same file.**
**Categories:** idiomatic.

### Nits

`KNOWN_FIELD_COUNT`'s doc says "the head's four" where `RECORD_HEAD_FIELDS` holds five
(pre-existing, four lines from a comment this commit corrected); the refusal message
interpolates an unbounded attacker-supplied value into a string that may be logged (bounded by
the 16 MiB header cap, and identical to the pre-existing `encoding_of` — one truncating helper
for all of them is the right shape, not a change to this commit).

## 7. Out of scope observations

- **`ALL_ENCODINGS` has M3's flaw and its completeness test the same fake guard** — pre-existing,
  Major-severity, demonstrated (253 green while the writer wrote what the reader refused). It
  wants the same one-source generation the shape half now has, and that is its own change:
  `FieldEncoding`'s variants carry parameters, so the macro is not the same macro.
- **The 17-way malformed-header probe found no defect.** Wrong TOML types, empty and uppercase
  and trailing-space spellings, an embedded NUL, a 200 kB value, a Cyrillic homoglyph, duplicate
  keys — all refused as `MalformedHeader` naming the field, the value and the closed set.
